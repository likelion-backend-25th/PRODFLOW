# 2장 이슈 관리

- 프로젝트를 진행하면서 발생하는 다양한 이벤트(버그, 추가해야 할 기능, 아이디어, 질문 등)를 등록하고 관리하는 기능

# 2. 레이블

- 이슈나 풀 리퀘스트 생성 시 사용할 레이블 관리
- Github Repository > Issues > Labels
  + 기존 레이블을 수정/삭제하거나 새로운 레이블을 추가해서 관리

## 2.1 일반적인 레이블 카테고리

### 2.1.1 우선순위(Priority)

- `Priority: High`: 가장 높은 우선순위의 이슈
- `Priority: Medium`: 중간 우선순위의 이슈
- `Priority: Low`: 우선순위가 낮은 이슈

### 2.1.2 유형(Type)

- `Type: bug`: 버그 수정이 필요한 이슈
- `Type: enhancement`: 기존 기능 개선
- `Type: feature`: 새로운 기능 추가
- `Type: documentation`: 문서와 관련된 이슈
- `Type: refactor`: 코드 리팩토링
- `Type: test`: 테스트 코드 관련 이슈

### 2.1.3 상태(Status)

- `Status: in progress`: 진행 중인 이슈
- `Status: needs review`: 검토가 필요한 이슈
- `Status: blocked`: 다른 작업에 의해 차단된 이슈

### 2.1.4 난이도(Difficulty)

- `Difficulty: easy`: 초급 개발자가 해결할 수 있는 이슈
- `Difficulty: medium`: 중간 난이도의 이슈
- `Difficulty: hard`: 고난이도의 이슈

### 2.1.5 범위(Scope)

- `Scope: frontend`: 프론트엔드 관련 이슈
- `Scope: backend`: 백엔드 관련 이슈
- `Scope: API`: API 관련 이슈
- `Scope: UI/UX`: 사용자 인터페이스 및 경험 관련 이슈

### 2.1.6 기타(Custom 레이블)

- `Etc: help wanted`: 외부의 도움이 필요한 이슈
- `Etc: wontfix`: 해결되지 않을 예정인 이슈
- `Etc: duplicate`: 중복된 이슈

# 3. 이슈로 지정하는 작업의 규모

- GitHub에서 이슈를 지정할 때, 하나의 이슈는 독립적으로 처리 가능한 작은 기능 단위가 되어야 하며 작업의 규모는 다음 기준에 따라 나눌 수 있지만, 팀이나 프로젝트의 특성에 맞춰 적절히 조정
- 코드 변경이 수반되는 기능 개발이나 버그 수정은 원칙적으로 이슈를 발행하여 관리하되, 단순 오타 수정 등 극히 사소한 변경의 이슈화 여부는 팀 규칙에 따라 유연하게 결정.

- 작업의 독립성
  + 하나의 이슈는 가능한 한 독립적인 작업이어야 함.
  + 다른 작업에 지나치게 의존하지 않고, 개별적으로 완료될 수 있는 단위로 나누는 것이 이상적

- 완료 시간
  + 이슈 하나는 짧게는 몇 시간에서 길게는 며칠 안에 완료할 수 있는 작업이 적당.
  + 일반적으로 1~3일 정도 소요되는 작업 단위로 나누는 것을 고려.
    - 프로젝트 기간(총 4주)을 고려하여 반나절에서 하루(길어도 2일 이내) 정도에 완료할 수 있는 작업 단위로 지정.
  + 너무 큰 작업이라면 여러개의 이슈로 세분화해서 관리

- 구체성
  + 이슈는 명확하고 구체적인 목표를 포함하도록 작성.
  + 예를 들어, "강좌 기능" 대신 "강좌 목록 및 QueryDSL 다중 조건 검색 UI", "챕터/차시 계층 구조 등록", "동영상 80% 진도율 저장 API", "포트원 결제 사전/사후 검증" 같은 작은 기능 단위로 나누어야 함.

- 기능적 측면
  + 하나의 이슈는 주로 하나의 기능 또는 버그 수정을 다루도록 지정.
  + 너무 많은 기능을 하나의 이슈로 묶으면 작업 관리가 어렵고, 진행 상황 추적이 힘들어짐.

# 4. 이슈 템플릿

- 이슈 작성시 버그 리포트 같은 경우 버그 현상, 재현 시나리오 등 이슈에 포함되어야 하는 내용을 입력 할수 있는 템플릿
- 참고: https://docs.github.com/ko/communities/using-templates-to-encourage-useful-issues-and-pull-requests/about-issue-and-pull-request-templates

## 4.1 이슈 템플릿 작성 실습
### 4.1.1 프로젝트 루트에 깃허브 이슈 템플릿 폴더 생성
```sh
mkdir -p ".github/ISSUE_TEMPLATE"
```

### 4.1.2 이슈 템플릿 폴더에 01-new-feature.md 파일 작성
```md
---
name: 기능 개발
about: 새로운 기능을 설계하고 구현할 때 사용
title: '[기능] 원하는 기능 설명'
---

## 기능 설명

추가하거나 개선할 기능에 대해 설명.

## 작업 내용

- [ ] 상세 작업 항목 1
- [ ] 상세 작업 항목 2

## 참고 자료

기능 개발 관련 참고 자료나 API 명세, 설계 내용 작성.
```

### 4.1.3 이슈 템플릿 폴더에 02-bug-report.md 파일 작성
```md
---
name: 버그 리포트
about: 발생한 버그를 보고하고 수정을 관리할 때 사용
title: '[버그] 문제 요약'
---

## 버그 설명

발생한 오류 현상 및 에러 로그(또는 스크린샷) 작성.

## 재현 방법

1. 재현 순서 또는 요청 조건 작성
2. 

## 기대 동작

정상적으로 동작했을 때 기대한 결과 작성.
```

- 회의를 거쳐서 팀에서 사용할 이슈 템플릿 작성

### 4.1.4 레포지토리에 이슈 템플릿 푸시
```bash
git add .
git commit -m "이슈 템플릿 추가"
git push
```

# 5. 이슈 생성
- Github Repository > Issues > New issue
  + 이슈 템플릿이 등록되어 있을 경우 템플릿중 하나를 선택하거나 `Blank issue`를 선택해서 빈 화면으로 시작
  + Add a title: 이슈의 제목을 입력. 간결하고 명확하게 작성하는 것이 좋음
  + Add a description: 이슈의 상세 내용을 입력. 버그 리포트의 경우 재현 방법, 기대 동작 등을 포함
  + 선택 사항
    - Assignees: 이슈를 담당할 팀원을 지정. 여러 명을 선택할 수 있음
    - Labels: 이슈의 유형, 우선순위, 범위 등을 나타내는 레이블을 선택. 여러 레이블을 선택할 수 있음
    - Type: 기본으로 제공되는 이슈 분류
    - Projects: 이슈를 연결할 프로젝트를 선택
    - Milestone: 이슈를 연결할 마일스톤을 선택. 스프린트나 릴리스 단위로 관리할 때 사용

## 5.1 이슈 생성 실습
- Github Repository > Issues > New issue > `기능 개발` 선택
  + Add a title: `[기능] 게시글 좋아요 기능 추가`
  + Add a description
    ```md
    ## 기능 설명
    사용자가 마음에 드는 게시글에 호감을 표현할 수 있도록 좋아요 기능 추가 필요.  
    동일한 사용자가 좋아요를 다시 누르면 취소되도록 토글 동작 지원.  
    게시글 조회 시 총 좋아요 수와 현재 로그인한 사용자의 좋아요 여부 확인 필요.

    ---

    ## 작업 내용
    - [ ] 사용자 ID와 게시글 ID를 복합 키 또는 유니크 제약조건으로 관리하는 좋아요 엔티티 설계
    - [ ] 좋아요 등록 및 취소를 처리하는 토글 서비스 로직 작성
    - [ ] 좋아요 등록/취소 요청을 처리하는 REST API 엔드포인트(`POST /api/posts/{postId}/likes`) 구현
    - [ ] 게시글 응답 DTO에 좋아요 총 개수 및 본인 좋아요 여부 필드 추가

    ---

    ## 참고 자료
    API 명세서의 좋아요 요청/응답 규격 및 ERD의 좋아요 테이블 연관관계 확인 필요.
    ```
  + Assignee: 해당 이슈를 처리할 담당자(팀원중 한명) 선택
  + Label: `Priority: Medium`, `Type: feature`, `Difficulty: medium`
  + Milestone: ` Sprint 2 (추가 개발)`
  + `Create`

# 6. 커밋 메시지와 이슈

## 6.1 커밋과 이슈 연결
- 커밋 메시지 입력 시 이슈 번호를 지정하면 커밋과 이슈를 연결시킬 수 있음

  ```
  feat: 게시글 좋아요 기능 추가

  #123
  ```

## 6.2 커밋과 이슈 종료
- 커밋 메시지 입력 시 이슈 번호와 다음 키워드를 같이 사용하면 이슈를 종료 시킬 수 있음

- `close`, `closes`, `closed`, `fix`, `fixes`, `fixed`, `resolve`, `resolves`, `resolved`

  ```
  feat: 게시글 좋아요 기능 추가

  close #123
  ```
