# 1. 박람회(행사)예약 관리 플랫폼

## 1.1 목적
- 웹서비스 기반(웹,모바일) 다수의 박람회/행사를 통합적으로 관리·홍보·예약·결제·입장검수까지 한 번에 처리할 수 있는 SaaS형 예약 관리 플랫폼을 구축
- 행사 운영자의 업무 효율성 향상, 참가자 예약 경험 개선, 유료 VIP 배너 광고 수익 창출, 정산 및 통계 자동화

## 1.2 필요성
- 각 박람회마다 예약·결제·입장 시스템을 별도로 구축하는 비용과 시간이 큼 → 공통 플랫폼 필요.
- 모바일웹을 통한 간편 예약이 시장 표준이 되었으나, 소규모/중소 행사들은 여전히 수기 접수(전화/메일/폼) 의존 → 예약 데이터 분산, 중복, 누락 문제.
- 참가자 확인 및 현장 입장 검수 시 명단 대조에 시간이 많이 걸림 → QR 기반 전자 티켓이 요구됨.
- 행사 노출 경쟁 심화 → 플랫폼 내 VIP 유료 배너 광고 슬롯을 통한 추가 수익 모델 가능.
- 운영사(전체 관리자)가 여러 박람회를 호스팅하고, 행사진행사(박람회 관리자)에게 개별 권한 위임하는 기능 필요.
- 정산, 통계(예약 수, 결제 금액, 참여자 현황) 자동화 요구 증가.

## 1.3 주요 사용대상(고객)

### 1.3.1 전체 관리자 (플랫폼 운영사)
- 플랫폼 전체 운영, 다수 박람회 생성, 광고/정산 관리
- 다중 행사 운영 효율, 수익화(VIP 배너), 데이터 집계
- 중앙 관리 콘솔, 다중 테넌트 관리, 광고 슬롯 설정, 일괄 통계/정산

### 1.3.2 박람회 관리자 (행사 주최 측)
- 특정 박람회 예약자/결제자/입장자 관리
- 실시간 예약 현황 파악, 참가자 명단 엑셀 추출, 콘텐츠(행사 소개/배너) 수정
- 행사별 관리자 계정/대시보드, 예약 명단 다운로드, 현장 입장체크 도구

### 1.3.3 고객/참가자 (End User)
- 모바일웹에서 행사 선택·예약·결제·입장확인
- 편리한 예약 절차, 결제 보안, 모바일 티켓(QR)
- 간편 예약 UX, 다중 행사 브라우징, 즉시 발급 QR 입장권

### 1.3.4 결제/정산 담당 회계팀 (확장)
- 행사별 매출, 수수료, 송금
- 정확한 정산 리포트
- 자동 정산 리포트 출력, 다운로드

### 1.3.5 마케팅/스폰서 (확장)
- VIP 배너 광고 집행
- 노출·클릭 추적
- 배너 등록/기간설정/성과통계

## 1.4 기능요구사항

### 1.4.1 역할/권한레벨
- 전체 관리자 (Super Admin) – 플랫폼 전역 설정, 박람회 생성/삭제, 관리자 계정 발급, VIP 광고 관리, 정산/통계 전체 접근.
- 박람회 관리자 (Event Admin) – 자신이 속한 박람회에 한해 예약현황, 결제내역, 참가자 정보, 콘텐츠(행사 소개/배너 이미지) 수정 가능.
- 고객 (User) – 행사 검색/필터, 예약, 결제, 예약확인, QR 입장권 조회.

## 1.5 메뉴

### 1.5.1 고객
- 홈 (행사 리스트 + VIP 배너)
- 행사 상세 (소개, 일정, 장소, 가격, 남은 티켓)
- 예약 폼 (인원/옵션 선택)
- 결제 (국내 PG, 해외 카드 선택 옵션)
- 예약 완료 & QR 티켓 발급
- 나의 예약 (예약내역, 취소/환불 요청, QR 재발급)

### 1.5.2 박람회 관리자 콘솔
- 대시보드 (예약 수, 결제 금액, 체크인율 등 지표)
- 예약자 명단 (필터링, 검색, 상태변경, 엑셀 다운로드)
- 콘텐츠 관리 (행사 소개문, 일정, 가격, 배너 이미지 교체)
- 현장 입장 스캐너 모드 (QR 스캔 & 체크인 처리)
- 통계 리포트 (기간별, 티켓종류별)
- 설정 (기본정보, 담당자 연락처, 노출 상태)

### 1.5.3 전체 관리자
- 전체 대시보드 (전체 플랫폼 KPI, 행사별 비교)
- 박람회 관리 (생성/수정/삭제, 코드/아이디/패스워드 발급)
- 계정 관리 (박람회 관리자 계정 할당/비활성)
- VIP 배너 광고 관리 (등록, 기간, 과금, 노출 우선순위)
- 결제/정산 (행사별 매출, 수수료, 송금 상태, 영수증)
- 통합 통계 (누적 예약자, 활성 유저, 인기 행사 등)
- 시스템 설정 (PG 연동키, 도메인, 이메일 템플릿, 로고)
- 로그/보안 (접속 로그)

## 1.10 주제 선택시 고려사항

### 1.10.1 기술 분석 요약
| 구분 | 내용 |
|---|---|
| 기술적 난이도 | 상 (High) |
| 난이도 선정 사유 | 전체 관리자, 행사 주최사, 일반 사용자 3단계 접근 권한 분기 및 주최사별 독립적인 데이터 분리 구조 설계가 기본이며, 부스 신청사(참가 기업) 권한 확장 시 부스 신청-심사(승인/반려)-배치 상태 머신 워크플로우 제어, 한정 좌석 예매 시 발생하는 트래픽 동시성 충돌 방지(JPA 비관적 락) 및 모바일 웹캠 스트림 제어 기반 실시간 QR 스캔 등 복합 기술 구현 요구 |
| 핵심 복잡도 | 3단계 권한 분기(부스 신청사 확장 시 4단계), 티켓 잔여 수량 동시성 제어, JPA 연관관계 N+1 방지, 부스 신청-심사 상태 제어 |
| 추가 학습 및 연동 기술 | 모바일 QR 티켓 발급 및 스캔, 부스 배치 시각화, 지도 위치 시각화, 통계 차트 라이브러리, Apache POI 엑셀 다운로드 |

### 1.10.2 추가 학습 및 외부 연동 기술
- 모바일 티켓 생성: 모바일 QR 티켓 발급([ZXing 라이브러리](https://github.com/zxing/zxing) 참고)
- 현장 입장 체크인: 웹 브라우저 웹캠 기반 QR 스캔 및 검수([html5-qrcode](https://github.com/mebjas/html5-qrcode) 참고)
- 부스 배치 시각화: 부스 신청사 확장 시 행사장 도면 및 인터랙티브 부스 구역 렌더링([HTML5 Canvas API](https://developer.mozilla.org/ko/docs/Web/API/Canvas_API) 참고)
- 행사장 위치 시각화: 행사 상세 페이지 내 행사장 위치 지도 표시([카카오 지도 Web API](https://apis.map.kakao.com/web/) 참고)
- 대시보드 데이터 시각화: 예약 추이 및 체크인율 통계 차트 구현([Recharts](https://recharts.org/) 또는 [Chart.js](https://www.chartjs.org/) 참고)
- 대량 명단 엑셀 추출: 참가자 명단 엑셀 파일 다운로드([Apache POI](https://poi.apache.org/) 참고)

### 1.10.3 프로젝트 추천 케이스 및 장단점
- 이 프로젝트를 추천하는 케이스:
  - 대규모 사용자 트래픽 처리와 티켓팅 동시 예매 로직을 깊이 있게 구현해보고 싶은 팀
  - 일반 참관객 예매(B2C)뿐만 아니라 참가 기업 부스 신청 및 심사/배정(B2B)까지 기능을 확장하여 구현해보고 싶은 팀
  - 모바일 웹 예약부터 현장 입장 QR 검수까지 온·오프라인 연계 서비스 흐름을 포트폴리오에 담고 싶은 팀
- 장점:
  - 한정 좌석 예매 시 발생하는 트래픽 동시성 충돌 방지(JPA 비관적 락) 및 데이터 정합성 해결 경험을 기술 면접에서 핵심 강점으로 제시 가능
  - 일반 관람객 대상의 티켓팅(B2C)과 부스 신청사 대상의 참가 신청 및 심사(B2B) 프로세스로 비즈니스 모델을 확장할 수 있어 다양한 도메인 설계 경험 확보 가능
  - 전체 관리자, 행사 주최사, (확장 시) 부스 신청사, 일반 사용자로 나뉘는 체계적인 권한 분리와 데이터 격리 구조 설계 역량 입증
  - 웹캠 QR 스캔, 행사장 지도 안내, 대시보드 통계 차트 등 시각적 완성도와 프론트/백엔드 결합 밀도가 높은 포트폴리오 제작 가능
- 단점:
  - 일반 관람객 예매에 더해 참가 기업 부스 신청 기능까지 동시에 개발할 경우 프로젝트 볼륨이 커질 수 있으므로 4주 스프린트 기간 동안 MVP(최소 기능 제품) 스코프 조절 필수
  - 티켓팅 동시 예매 처리 및 모바일 브라우저 카메라 권한 연동 등 기술적 난도가 높은 요소에 대한 사전 검증 필수

# 2. 영업사원을 위한 견적 생성 및 관리 시스템

## 2.1 개요
- 외부 영업사원이 태블릿 기반으로 실시간 제품 탐색 및 고객 상담 중 견적서를 작성하고, 출력 또는 이메일 전송이 가능하도록 하는 웹 기반 견적서 생성 플랫폼

## 2.2 배경 및 필요성
- 기존 종이 견적서 또는 수기 작성 방식은 비효율적이며, 데이터 관리가 어렵고, 고객에게 신뢰도 낮음
- 본 시스템은 디지털 기반의 실시간 견적 기능을 제공하여 영업 효율과 신뢰도 제고

## 2.3 주 사용대상
- 외부 영업사원: 고객과 상담하며 제품 탐색 및 견적서 생성
- 최고관리자: 사용자 승인, 제품 정보 관리, 견적서 모니터링

## 2.4 기능 요구사항

### 2.4.1 공통
| 구분 | 내용 |
|---|---|
| 회원가입 | 이메일, 이름, 휴대폰, 소속 회사 입력 후 가입 요청 전송 |
| 승인제도 | 최고관리자가 승인해야만 로그인 및 서비스 이용 가능 |
| 소셜 로그인 | Google, Kakao 등 소셜 계정 연동 (선택사항) |
| 권한분리 | 관리자와 영업사원으로 명확한 접근 권한 구분 |
| 반응형 | 태블릿(10~12인치 기준) 및 데스크탑 브라우저 대응 UI |

### 2.4.2 영업사원- 제품탐색
| 항목 | 내용 |
|---|---|
| 카테고리 탐색 | 2~3단계 분류 트리 구조로 제품 탐색 가능 |
| 제품 검색 | 키워드 검색 (제품명, 키워드, 제품코드 등) |
| 즐겨찾기 | 자주 사용하는 제품 즐겨찾기 등록 기능 |
| 제품 상세정보 | 제품 이미지, 설명, 규격, 단가 등 열람 가능 |

### 2.4.3 영업사원 - 견적 작성
| 항목 | 내용 |
|---|---|
| 제품 선택 | 제품 클릭 → 수량 입력 → 견적 목록에 추가 |
| 견적 목록 보기 | 선택한 제품들의 목록, 수량, 소계 자동 계산 |
| VAT 설정 | VAT 포함/미포함 선택 → 총액 자동 계산 반영 |
| 할인 적용 (선택) | 단가별 할인율 직접 입력 또는 관리자 사전 설정 기준 사용 가능 |
| 고객정보 입력 | 고객명, 연락처, 이메일, 주소 입력 |
| 견적서 미리보기 | 최종 견적서 문서 미리보기 화면 제공 (PDF 또는 이미지 형태) |
| 견적서 다운로드 | PDF, 이미지(JPEG/PNG) 형식으로 저장 가능 |
| 이메일 전송 | 고객 이메일로 견적서 전송 가능 (전송 이력 저장) |

### 2.4.4 최고 관리자 기능-고객관리
| 항목 | 내용 |
|---|---|
| 회원가입 승인 | 가입 요청 리스트 조회, 승인/거절 처리 |
| 사용자 목록 | 전체 사용자 리스트 조회 및 검색 |
| 사용자 수정 | 소속, 연락처, 이메일 등 정보 수정 가능 |
| 사용자 비활성화 | 로그인을 제한하거나 퇴사자 처리 기능 제공 |

### 2.4.5 최고 관리자 기능-제품관리
| 항목 | 내용 |
|---|---|
| 카테고리 구조 관리 | 대분류, 중분류, 소분류 추가/삭제/순서 변경 |
| 제품 등록 | 제품명, 코드, 이미지, 설명, VAT 설정, 단가, 출고가 등 입력 |
| 제품 수정/삭제 | 제품 데이터 편집 또는 삭제 (단, 견적서와 연결된 제품은 삭제 제한) |
| 이미지 업로드 | 제품 썸네일, 상세 이미지 업로드 가능 (최대 용량 제한 필요) |

### 2.4.6 최고 관리자 기능-견적서 관리
| 항목 | 내용 |
|---|---|
| 견적서 리스트 | 전체 사용자 작성 견적서 목록 조회 |

| 견적서 다운로드 | 관리자도 PDF 또는 이미지로 다운로드 가능 |
| 견적서 삭제 | 필요 시 견적서 삭제 또는 비공개 처리 가능 |

| 기능 | 설명 |

## 2.6 주제 선택시 고려사항

### 2.6.1 기술 분석 요약
| 구분 | 내용 |
|---|---|
| 기술적 난이도 | 중 (Medium) |

### 2.6.2 추가 학습 및 외부 연동 기술
- 견적서 정형 문서 변환: 서버 사이드 PDF 문서 생성([OpenPDF](https://github.com/LibrePDF/OpenPDF) 참고) 또는 클라이언트 브라우저 렌더링 기반 변환([html2canvas](https://html2canvas.hertzen.com/) 및 [jsPDF](https://github.com/parallax/jsPDF) 참고)
- 고객 전자 서명 패드: 태블릿 화면 기반 고객 확인 서명 캡처([react-signature-canvas](https://github.com/agilgur5/react-signature-canvas) 참고)
- 이메일 발송 자동화: 견적서 PDF 첨부 파일 전송 및 SMTP 연동([Spring Boot Starter Mail](https://docs.spring.io/spring-boot/docs/current/reference/html/io.html#io.email) 참고)
- 영업 실적 시각화: 담당자별 견적 건수 및 인기 품목 통계 차트 구현([Recharts](https://recharts.org/) 참고)

### 2.6.3 프로젝트 추천 케이스 및 장단점
- 이 프로젝트를 추천하는 케이스:
  - 복잡한 데이터베이스 설계와 실시간 계산 로직을 정교하게 다루는 백엔드 기본기를 확실히 증명하고 싶은 팀
  - 실제 기업에서 사용하는 업무 도구(B2B 영업 관리 시스템)를 만들어 실무 적응력을 어필하고 싶은 팀
  - 태블릿 반응형 UI, 전자 서명, 규격화된 PDF 문서 생성 등 실무 비즈니스 문서 워크플로우를 포트폴리오에 담고 싶은 팀
- 장점:
  - 계층형 카테고리 트리 설계 및 금액 계산(단가, 수량, 소계, 할인율, VAT)을 프론트와 백엔드 양쪽에서 오차 없이 검증하는 꼼꼼한 개발 역량 어필 가능
  - 서버/클라이언트 PDF 생성, 캔버스 서명 패드, 메일 발송 등 실무 비즈니스 문서 워크플로우를 완성도 높게 구현한 차별화된 포트폴리오 구성 가능
  - 외부 연동 의존도가 낮아 데이터베이스 정규화, JPA 지연 로딩 최적화, 클린 코드 작성에 집중하여 높은 완성도 확보 가능
- 단점:
  - 대규모 트래픽이나 복잡한 인프라 구조를 다루지 않아 기술적인 화려함을 어필하는 데에는 다소 한계가 있을 수 있음
  - 금액 계산 오차나 PDF 한글 깨짐 같은 사소한 결함 발생 시 도메인 신뢰도가 저하될 수 있으므로 정밀한 테스트 필요

# 3. 생산 예정 및 과거 생산기록의 체계적 관리를 위한 생산 관리 서비스

## 3.1 목적
- 생산시설의 생산 예정 및 과거 생산기록을 체계적으로 관리하기 위한 내부 전산화 플랫폼을 구축

## 3.2 배경
- 기존 수기 및 유선 방식의 발주 처리 과정에서 발생하는 누락 및 혼선 문제를 방지하고, 기록 보존과 데이터 기반 운영을 가능하게 하기 위함.

## 3.3 주 사용대상
- 생산시설 종사자(내부 임직원)

## 3.4 기능 요구사항

### 3.4.1 공통
| 항목 | 설명 |
|---|---|
| 로그인 | 내부 전용 계정 기반 로그인 (외부 접근 제한) |
| 계정관리 | 최고 관리자에 한하여 내부 전용 계정들을 관리(추가, 삭제, 수정 등) |

### 3.4.2 클라이언트 관리
| 항목 | 설명 |
|---|---|
| 클라이언트 등록/조회 | 회사명, 대표자명, 주소, 연락처 등 등록 및 조회 |
| 클라이언트 자동완성 | 수주 등록 시 기존 클라이언트 자동완성 및 자동입력 |
| 클라이언트 자동 추가 | 수주 등록 시 존재하지 않는 클라이언트는 자동 등록 처리 |
| 엑셀 일괄등록 | 양식 기반 엑셀 업로드로 클라이언트 대량 등록 |

### 3.4.3 제품관리
| 항목 | 설명 |
|---|---|
| 생산품목 등록/조회 | 생산 가능한 제품 목록 관리 (명칭, 설명 등) |
| 품목 자동완성 | 수주 등록 시 기존 품목 자동완성 및 자동입력 |
| 신규 품목 추가 | 수주 등록 시 존재하지 않는 품목은 자동 등록 처리 |

### 3.4.4 수주 등록 및 관리
| 항목 | 설명 |
|---|---|
| 수주 등록 | 클라이언트 + 생산품목 + 수량 + 납기일 + 배송지 입력 |
| 자동입력 | 클라이언트 및 품목 선택 시 관련 필드 자동입력 |
| 금액 계산 | 수량, 단가, VAT 포함 여부 기준 총액 자동 산정 |
| 상태 관리 | 수주 상태(대기, 생산중, 배송중, 완료 등) 변경 가능 |
| 입금 확인 | 수주별 입금 여부 등록 및 확인 기능 제공 |

### 3.4.5 알림 및 통계
| 항목 | 설명 |
|---|---|
| 배송 알림 | 배송 시작 시 SMS 또는 메신저로 클라이언트에게 발송 |
| 통계 대시보드 | 수주 건수, 생산량, 납기 이행률, 품목별 분포 등 시각화 |

|---|---|

| 난이도 선정 사유 | 기업 내부 전산 관리 시스템으로서 기준 정보(거래처, 품목)와 수주-생산 공정 간의 엄격한 데이터 무결성 및 연관관계 설계가 필수적이며, 수주 등록 시 실시간 검색 디바운스 자동완성 및 수주 납기일/생산 일정을 시각화하는 캘린더 뷰 구현, 대량 엑셀 양식 파싱 및 행 단위 유효성 검증 예외 처리가 요구됨 |
| 핵심 복잡도 | 수주-생산-배송 라이프사이클 상태 머신 제어, 생산 일정 시각화, 엑셀 대량 일괄 등록 및 파싱 |
| 추가 학습 및 연동 기술 | 생산 일정 캘린더 뷰, Apache POI 대용량 엑셀 파싱 및 검증, 검색 디바운스 자동완성, 외부 SMS 연동, 공정 통계 차트 |

### 3.6.2 추가 학습 및 외부 연동 기술
- 생산 일정 캘린더 시각화: 수주 납기일 및 생산 예정 공정 일정 캘린더 뷰 구현([FullCalendar](https://fullcalendar.io/) 참고)
- 대량 엑셀 일괄 등록: 클라이언트 및 품목 엑셀 양식 데이터 파싱 및 행 단위 유효성 검증([Apache POI](https://poi.apache.org/) 참고)
- 검색 자동완성 최적화: 수주 등록 시 거래처/품목 실시간 검색 디바운스([Lodash Debounce](https://lodash.com/docs/#debounce) 참고)
- 알림 메시지 발송: 배송 시작 트리거에 따른 고객 문자 발송([CoolSMS](https://coolsms.co.kr/) 또는 [솔라피](https://solapi.com/) 참고)
- 공정 지표 시각화: 품목별 생산 분포 및 납기 이행률 통계 차트 구현([Recharts](https://recharts.org/) 참고)

### 3.6.3 프로젝트 추천 케이스 및 장단점
- 이 프로젝트를 추천하는 케이스:
  - 기업용 솔루션 및 SI 개발자 채용에서 가장 선호하는 기업 내부 전산 관리 시스템 구축 역량을 증명하고 싶은 팀
  - 대량 엑셀 일괄 등록, 검색어 자동완성, 생산 일정 캘린더 등 기업의 방대한 데이터를 체계적으로 관리하는 역량을 보여주고 싶은 팀
  - 거래처와 생산 품목, 수주와 생산 공정 간의 얽힌 데이터를 빈틈없이 정돈하는 데이터베이스 모델링 실력을 어필하고 싶은 팀
- 장점:
  - 거래처-품목-수주 공정 간의 엄격한 데이터 무결성 및 연관관계 설계를 통해 엔터프라이즈 데이터베이스 모델링 실력 입증 가능
  - Apache POI 기반 대용량 엑셀 파싱 및 행 단위 유효성 검증, 에러 리포트 생성 등 실무 관리자 기능 구현 역량 강조 가능
  - 수주 납기일과 생산 공정을 한눈에 파악하는 캘린더 화면과 공정 통계 차트를 통해 업무 효율을 높인 사례로 면접에서 스토리텔링 유리
- 단점:
  - 수주, 생산, 발주, 납기 등 제조업 현장 업무 흐름에 대한 사전 도메인 스터디가 선행되지 않을 경우 기능 설계가 흔들릴 수 있음
  - 사내 직원 전용 폐쇄형 시스템이라 화면이 다소 정적으로 보일 수 있어 캘린더 뷰와 인터랙티브 통계 차트 시각화에 집중 필요

# 4. 고객의 요청 및 수리 처리 내역을 관리하는 통합 A/S 접수 및 처리 시스템

## 4.1 목적
- A/S 센터에서 발생하는 고객 요청 및 수리 처리 내역을 체계적으로 전산화하여 업무 효율성과 고객 응대 품질을 향상시키고, 처리 이력의 통계를 확보

## 4.2 배경
- 전화, 메모, 엑셀 등으로 관리되던 A/S 업무를 체계화함으로써 누락 방지, 담당자 분배, 처리 추적, 입금 확인 등 다양한 업무 과정을 일관된 방식으로 처리

## 4.3 주 사용대상
- 내부 직원 (A/S 기사, 접수 담당자)
- 최고관리자 (계정 관리, 전체 데이터 모니터링)

## 4.4 기능요구사항

### 4.4.1 공통
| 항목 | 설명 |
|---|---|
| 로그인 | 내부 계정 기반 로그인 (외부 노출 없음) |
| 권한 제어 | 최고관리자와 일반 직원 권한 분리 |
| 계정 관리 | 계정의 정보 및 아이디 관리 |
| 수리내역 프리셋 | 자주사용되는 수리내역(내역 명 및 수리비용) 프리셋화 및 관리 |

### 4.4.2 고객 및 제품관리
| 항목 | 설명 |
|---|---|
| 고객 목록 관리 | 고객명, 연락처, 주소 등 CRUD |
| 엑셀 일괄등록 | 고객 데이터 다량 등록 지원 |
| 제품 목록 관리 | A/S 가능한 제품 항목 목록 등록 및 수정 가능 |
| 자동완성 | 접수 시 고객/제품 필드 자동완성 및 자동입력 지원 |
| 수동입력 | 존재하지 않는 데이터도 자유롭게 입력 가능 (자동 등록 가능 여부 설정) |

### 4.4.3 A/S 접수 및 처리 흐름
| 항목 | 설명 |
|---|---|
| 접수 등록 | 고객 선택, 제품 선택, A/S 요청 내용 입력 |
| 접수 알림 | 접수 완료 시 SMS로 고객에게 안내 |
| 상태 관리 | 상태 흐름: 접수 → 수리 중 → 입금대기 → 배송대기 → 완료 |
| 담당자 지정 | 내부 계정 기준 담당자 지정 |
| A/S 내역 | 수리 내역 입력, 수리내역 프리셋을 통해 쉽게 선택 가능 |
| 주소 검색 | 배송지 입력 시 주소 검색 라이브러리 연동 (예: 다음 주소 API) |

### 4.4.4 금액 산정 및 입금관리
| 항목 | 설명 |
|---|---|
| 수리 금액 계산 | 제품 및 수리 항목에 따라 자동 금액 산정 |
| 입금요청 | 수리 완료 시 고객에게 가상계좌번호 포함 SMS 발송 |
| 가상계좌 연동 | PG사 연동 통한 가상계좌 발급 및 입금 확인 콜백 처리 |
| 입금 상태 | 입금 완료 시 자동 상태 변경 또는 수동 처리 가능 |

### 4.4.5 배송 및 완료 처리
| 항목 | 설명 |
|---|---|
| 배송 알림 | 배송 시작 시 SMS로 고객에게 발송 시작 안내 |
| 송장번호 입력 | 송장번호 등록 → 상태 '완료'로 변경 |
| A/S 완료 처리 | 배송 후 최종 완료 처리 |

### 4.4.6 통계 및 대시보드
| 항목 | 설명 |
|---|---|
| 요약 통계 | 월별 접수 수, 처리 완료 수, 미입금 건수 등 |
| 필터링 | 제품별, 담당자별, 상태별 필터 제공 |
| 시각화 | 상태별 건수 분포, 접수 대비 완료 비율 등 대시보드 지원 |

### 4.6.1 기술 분석 요약

|---|---|

| 추가 학습 및 연동 기술 | 택배 배송 추적 API, 도로명 주소 검색 연동, 단계별 SMS 자동 발송, 실적 통계 차트 |

- 택배 배송 추적 연동: 송장번호 기반 택배사 실시간 배송 상태 조회([스마트택배 API](https://info.sweettracker.co.kr/) 또는 [택배조회 오픈 API](https://tracker.delivery/) 참고)
- 주소 검색 라이브러리 연동: 배송지 도로명 주소 검색 연동([카카오 우편번호 서비스](https://postcode.map.daum.net/guide) 참고)
- SMS 자동 알림 발송: 접수 완료, 배송 시작 등 단계별 문자 발송([솔라피](https://solapi.com/) 또는 [CoolSMS](https://coolsms.co.kr/) 참고)
- A/S 실적 대시보드: 월별 접수 건수 및 처리 상태별 분포 통계 차트 구현([Recharts](https://recharts.org/) 참고)

### 4.6.3 프로젝트 추천 케이스 및 장단점
- 이 프로젝트를 추천하는 케이스:
  - 접수부터 수리, 배송, 완료까지 이어지는 단계별 업무 진행 상태 흐름 제어 역량을 백엔드 포트폴리오의 핵심 무기로 삼고 싶은 팀
  - 도로명 주소 찾기, 실시간 택배 배송 조회, 단계별 자동 문자 통보 등 실생활과 밀접한 외부 연동 기능을 풍부하게 경험하고 싶은 팀
  - 서비스 기사의 현장 업무와 본사 관리자의 데이터 모니터링이 결합된 실무 사후 관리 시스템을 구축해보고 싶은 팀
- 장점:
  - 접수 → 수리 중 → 입금대기 → 배송대기 → 완료로 이어지는 5단계 상태 흐름을 JPA 변경 감지와 트랜잭션으로 엄격하게 통제하여 잘못된 상태 전이를 원천 차단하는 백엔드 설계 실력 어필 가능
  - 택배사 배송 추적 API 및 주소 검색 서비스 등 외부 시스템 연동 시 발생할 수 있는 지연이나 오류를 깔끔하게 대처한 예외 처리 경험을 면접에서 효과적으로 설명 가능
  - 표준 수리비 기준표와 담당 기사의 현장 금액 수정을 유연하게 결합한 실무형 금액 산정 모델링을 통해 실무 적응력 입증
- 단점:
  - 5단계 라이프사이클 전이에 따른 상태별 제약 조건이 촘촘하여 데이터 흐름 검증과 상태 전이 테스트에 많은 공수 투입 필요
  - 외부 택배사 조회 시스템이 느려지거나 멈췄을 때 화면이 멈추지 않도록 오류 대비 로직을 꼼꼼하게 작성해야 함
