## 1. 기획 개요

### 1.1 프로젝트 배경 및 목적

- 생산시설에서 수기·유선으로 처리하던 발주·수주 업무의 누락·혼선을 줄이고, 수주·생산·입금·포장·출고·운송장 조회까지 한 시스템에서 처리하는 **내부 전산화 플랫폼** 구축.
- 거래처(거래처)·생산 품목·수주·작업 지시를 한곳에서 관리하고, 수주 상태(대기 → 생산대기 → 생산중 → 포장중 → 출고대기 → 배송중 → 완료)를 따라가며 현장 업무를 표준화.
- 배송 시작 시 SMS 또는 이메일로 거래처에 안내하여, 출고 사실을 빠짐없이 전달.
- 수주 건수, 생산량, 납기 이행률, 품목별 분포 등 통계 대시보드로 데이터 기반 운영을 지원.
- 외부 고객용 웹·회원가입 없이 **내부 임직원 전용**으로 폐쇄형 운영하여 접근 통제.
- Spring Boot 기반 REST API 백엔드와 React 기반 거래처 간 비동기 데이터 통신 체계 확립.
- 영속화는 Spring Data JPA + MySQL로 단순화하여 엔터프라이즈형 도메인 모델링에 집중.

### 1.2 서비스 주요 특징

- JWT 기반 내부 계정 인증·인가. 최고 관리자 / 수주 관리자 / 생산 현장 관리자/업무 조회 담당자 역할 분리.
    - 최고 관리자: 계정 관리, AI 사용, 수주 관리자 및 생산 현장 관리자 권한 포함
    - 수주 관리자: 수주·품목·거래처 등록·수정.
    - 생산 현장 관리자: 수주, 제품, 거래처, 작업 지시 조회, 생산 작업 상태(시작/중지/일시정지/완료) 변경
    - 업무 조회 담당자: 수주, 제품, 거래처, 작업 지시 등의 업무 정보만 조회
- 거래처·생산품목 기준정보 CRUD
- 수주 등록 시 거래처 자동완성 및 미존재 시 자동 등록.
- 양식 기반 엑셀 업로드로 거래처 대량 등록.
- 수주별 수량·단가·VAT 기준 총액 자동 산정.
- 수주 상태 머신(대기 → 생산대기 → 생산중 → 포장중 → 출고대기 → 배송중 → 완료) 및 상태 이력 관리.
- 수주별 입금 여부를 PG 가상계좌 + 웹훅 자동화로 파악후 상태 이력 변경 (가상계좌 연동)
- 배송: 송장·택배사 수동 입력 **+** 배송 시작 시 SMS/메신저 알림 (택배 배송조회 API 연동).
- 통계 대시보드(수주 건수, 생산량, 납기 이행률, 품목별 분포).
- 생산 일정관리 캘린더, AI 비서

## 2. 주요 기능 요구사항

### 2.1 계정 및 인증 관리 기능

- 내부 전용 계정 기반 로그인 (외부 공개 회원가입 없음).
- JWT 기반 로그인 및 토큰 발급.
- 최고 관리자 / 수주 관리자 / 생산 현장 관리자 / 업무 조회 담당 권한 분리.
- 최고관리자에 한한 내부 계정 추가·수정·삭제·비활성화.
- 로그인 사용자의 기본 정보 조회.

### 2.2 거래처(거래처) 관리 기능

- 거래처 등록·조회·수정 (회사명, 대표자명, 주소, 연락처 등).
- 거래처 직접 등록시 주소는 주소 API 연동
- 양식 기반 엑셀 업로드로 거래처 대량 등록.
- 수주 등록 시 기존 거래처 자동완성 및 자동입력.
- 수주 등록 시 존재하지 않는 거래처는 자동 등록 처리.

### 2.3 생산품목 관리 기능

- 생산 가능 품목 등록·조회·수정 (제품명, 모델명, 설명, 금액 등).
- 수주 등록 시 기존 품목 자동완성 및 자동입력.
- 수주 등록 시 존재하지 않는 품목은 자동 등록 처리.
- 품목 금액 변경시 과거의 수주 금액은 변경처리 하지 않음

### 2.4 수주 등록 및 상태 관리 기능

- 수주 등록: 거래처 + 품목 1줄 이상(품목·수량·단가·VAT) + 희망 납기일 + 배송지 + 수신 연락처 + 알림 채널(SMS/이메일) + 메모.
    - 현장 담당자·생산라인은 등록하지 않음.
- 수주 등록 시 수주 등록 상태 ‘예정’**.**
- 계약금(선금) 입금이 확인되면 수주 등록 상태가 ‘확정’ (PG 웹훅)으로 되고 수주 상태는 생산대기 상태로 된다. 이후 작업지시서를 자동 등록한다.
- 정해진 일자까지 계약금이 없으면 수주·작업지시 취소는 수동.
- 수주 상태와 작업지시 상태는 분리하여 관리한다.
- 거래처·생산품목 선택 시 관련 필드 자동입력.
- 수량·단가·VAT 포함 여부 기준 총액 자동 산정.
- 수주 상태 관리: 대기 → 생산대기 → 생산중 → 포장중 → 출고대기 → 배송중 → 완료
    - 대기 : 수주 정보 수정 및 취소 (수주 작성 후 입금 전)
    - 생산 보류: 기기 점검 및 고장시 (수동)
    - 생산대기 : 선금 완료 된 상태 (자동) - 작업지시서 작성 후 생산 시작/중지 버튼
    - 생산중 : 수량, 단가, 납기일 수정 허용 여부 (수동)
    - 포장중: 생산 완료 버튼 클릭시, 가공 완료된 제품을 포장 시 상태 (수동)
    - 포장완료: 포장 완료 후 배송 기사가 오기 전까지 대기하는 상태 (수동)
    - 배송중 : 배송지 수정 허용 여부
    - 완료 : 일반 직원 수정 제한
- 상태 변경 이력(이전 상태, 이후 상태, 시각, 처리자) 저장.
- 수주 목록 검색·필터 (상태, 납기, 거래처, 입금 여부 등).
- 수주 상세 조회.
- 납기 가능일 계산은 라인 미배정 기준으로 일자별 공장 생산량을 계산하여 정함. (납기일 = 생산완료예정일 + 2일)

### 2.5 견적서 생성 및 관리

견적서는 별도 문서를 새로 작성하지 않는다. 등록된 수주의 거래처, 품목, 수량, 단가, 납기를 읽어 만든다. 수주 상세의 견적서에서 확인하고, 수주 진행 상태와 입금 상태는 바꾸지 않는다.

- 수주 관리자와 최고 관리자만 생성·발송할 수 있다. 취소된 수주는 견적서를 만들지 않는다.
- 문서에 넣는 값
    - 수주번호, 발행일, 거래처명, 대표자, 담당자, 연락처
    - 품목(제품명·기종), 수량, 단가, VAT 포함/별도, 줄 금액
    - 공급가액, 부가세, 총액, 계약금(총액의 50%), 잔금
    - 계약금 입금 마감일(생산 시작 예정일 -1)**,** 생산 시작 예정일, 생산 완료 예정일, 희망 납기일, 배송지
- 금액은 견적서를 만드는 시점의 수주 품목으로 계산한다. 이후 수주의 수량·단가가 바뀌어도 이미 만든 견적서는 바뀌지 않는다. 다시 만들면 새 문서로 저장한다.
- 견적서를 PDF로 변환해 내려받을 수 있다. 화면에서 보는 항목과 PDF 항목은 같다.
- 견적서에 암호를 걸어서 거래처 대표자의 전화번호 뒷자리를 입력을 해야 확인이 가능하게 보안 처리
- 발송 채널은 문자와 이메일이다. 수신 연락처와 이메일은 그 수주의 거래처 정보를 기본값으로 채우고, 보내기 전에 수정할 수 있다.
- 발송할 때마다 채널, 수신처, 성공/실패, 발송 시각을 남긴다. 실패하면 사유를 저장하고 수주 상태는 그대로 둔다.

### 2.6 입금 관리 기능

- PG사 (결제대행사)가 제공하는 실시간 계좌이체 및 무통장 입금용 가상계좌 발급 API 연동
- PG사의 입금완료 웹훅 콜백 API를 수신하여 수주건의 입금 상태를 자동으로 업데이트

  (미입금 →부분입금(선입금)→입금완료(후입금))
- 입금 완료 시 입금 시각 결제 승인번호 저장
- 입금 상태와 수주 진행 상태(대기~완료)는 독립적으로 관리.

### 2.7 배송 알림 기능

- 택배사 배송조회 API연동

  택배사 선택 및 운송장 번호 입력 시 외부 배송 조회 api와 연동

### 2.8 통계 및 대시보드 기능

- 수주 건수, 생산량, 납기 이행률, 품목별 분포 시각화.
- 상태별 파이프라인 요약 (대기 / 생산중 / 배송중 / 완료 건수).
- 납기 임박·지연 수주 표시, 미입금 현황 요약, 납기·출고 캘린더 뷰.
- 주요 업무 이벤트 알림 (납기 위험, 작업지시서 변경 등)

### 2.9 생산 라인 및 작업 할당 관리 기능

- 공장 내 생산 라인(예: 1라인, 2라인 등) 상태 및 가동 현황 관리.
    - 전체 생산라인 현황 페이지
    - 최고관리자만 신규 라인 등록 페이지 및 라인 정보 수정 가능
    - 현장 관리자는 라인 상태(가동가능/가동 중/점검 중/고장) 관리
    - 라인별 상세 정보 조회
- 생산대기 상태의 작업지시서를 현장 담당자가 확인하고, 생산 가능한 라인을 선택하여 배정.
- 배정 조건은 작업지시서의 생산 수량을 처리할 수 있고, 해당 기간에 생산 여유가 있는 라인
- 라인 배정 후 작업지시서에 생산라인 정보를 저장하고, 생산 시작 버튼을 통해 작업 상태를 생산중으로 변경.
- 생산 시작 시 배정한 라인을 기준으로 하되, 설비 고장 등 현장 상황 발생 시 현장 담당자가 작업지시서를 수정하여 다른 라인으로 변경할 수 있도록 함.
- 라인별로 현재 작업 중인 수주목록 및 담당 직원 현황을 실시간 시각화.
- 작업자별 작업 진행 상황 업데이트 및 작업 완료 보고 기능.

### 2.10 AI 챗봇 기능

- 사용자가 자연어로 업무 데이터를 질문할 수 있는 대화 페이지 제공
- 대화 내역 저장 및 이전 대화 조회
- 사용자의 질문을 AI가 분석하여 데이터베이스 조회용 SQL 생성
- 조회 권한만 갖고있는 계정으로 SQL 실행
- 조회 결과를 이해하기 쉬운 문장과 표 형태로 제공
- 데이터 조회에 필요한 허용된 테이블과 컬럼만 사용하도록 제한
- SELECT 조회 쿼리만 허용하고 INSERT, UPDATE, DELETE 등 데이터 변경 쿼리 차단
- SQL 실행 전 검증 및 사용자 권한 확인
- 조회 결과가 없거나 SQL 생성 및 실행에 실패한 경우 안내 메시지 제공

## 3. **비기능 요구사항 및 기술 스택**

### 3.1 **시스템 아키텍처 및 기술 스택**

- 영속성 및 ORM: Spring Data JPA, Hibernate, OpenFeign, QueryDSL 7.x

### 3.2 데이터 정합성 및 쿼리 성능 최적

- 선언적 트랜잭션 관리: 수주·생산계획·생산실적 등록 및 수정 시 `@Transactional`을 활용하여 연관 데이터의 원자성과 정합성 확보.

- 인덱스 최적화: 수주번호, 생산일자, 진행 상태 등 주요 검색 조건에 인덱스를 적용하여 조회 성능 개선.
