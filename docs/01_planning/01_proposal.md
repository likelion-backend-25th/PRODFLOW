## 1.1 기획 개요

### 1.1.1 프로젝트 배경 및 목적

- 수기·구두 중심 업무 흐름의 전산화 및 표준화
    - 기존 제조 현장에서 수기 노트, 엑셀, 유선 통화 등으로 파편화되어 관리되던 발주·수주·생산·입금·출고 업무를 단일 통합 플랫폼으로 구축하여, 데이터 누락 및 소통
      혼선을 근본적으로 방지합니다.
- 수주-생산-결제 간 실시간 자동화 파이프라인 구축
    - 수주 등록 시 공장 가용 생산량을 계산하여 납기 가능일을 정하고, PG 가상계좌 웹훅(Webhook)을 통해 선금(계약금) 입금이 확인되는 즉시 작업지시서를
      자동으로 발행하여 생산 대기 상태로 전환하는 자동화 프로세스를 확립합니다.

### 1.1.2 서비스 핵심 가치

- 스마트 자동화 (Smart Automation): 수주 등록 시 일자별 공장 가용량 계산부터 선금 입금 시 작업지시서 자동 생성, 배송 상태 변경 시 거래처 알림 자동 발송까지 인간의 개입을 최소화한 연쇄
  자동화를 실현합니다.
- 유연한 현장 대응성 (Flexible Agility): 생산대기 상태의 작업지시서를 현장 담당자가 실시간 가용 라인에 맞춰 배정하고, 돌발적인 설비 고장 시 라인 재배정 및 작업 상태(시작/중지/일시정지/완료)를
  능동적으로 제어합니다.

### 1.1.3 기대 효과

- 수주 후 작업지시서 작성 및 결제 확인 절차가 웹훅과 자동화 로직으로 처리되어 수동 확인 시간이 획기적으로 줄어들고 전체 공정 리드타임이 단축됩니다. 거래처·품목·수주·작업 지시의 통합 관리를 통한 현장 응대 및
  이력 조회 효율성 향상.
- 실시간 라인 현황판을 통해 설비 병목 현상을 방지하고, 직원의 유동적 배치를 통해 생산 효율을 극대화합니다.
- 정확한 납기일 계산, 선금 입금 확인 즉시 생산 착수, 배송 시작 알림 및 운송장 배송 추적 서비스를 통해 거래처 대응의 신뢰성과 만족도를 제고합니다.

## 1.2 주요 기능 요구사항

### 1.2.1 계정 및 인증 관리 기능

- 내부 전용 계정 기반 로그인 (외부 공개 회원가입 없음).
- JWT 기반 로그인 및 토큰 발급.
- 최고 관리자 / 수주 관리자 / 생산 현장 관리자 / 업무 조회 담당 권한 분리.
- 최고관리자에 한한 내부 계정 추가·수정·삭제·비활성화.
- 로그인 사용자의 기본 정보 조회.

### 1.2.2 거래처 관리 기능

- 거래처 등록·조회·수정 (회사명, 대표자명, 주소, 연락처 등).
- 거래처 직접 등록시 주소는 주소 API 연동.
- 양식 기반 엑셀 업로드로 거래처 대량 등록.
- 수주 등록 시 기존 거래처 자동완성 및 자동입력.
- 수주 등록 시 존재하지 않는 거래처는 자동 등록 처리.

### 1.2.3 생산품목 관리 기능

- 생산 가능 품목 등록·조회·수정 (제품명, 모델명, 설명, 금액 등).
- 수주 등록 시 기존 품목 자동완성 및 자동입력.
- 수주 등록 시 존재하지 않는 품목은 자동 등록 처리.
- 품목 금액 변경시 과거의 수주 금액은 변경처리 하지 않음.

### 1.2.4 수주 등록 및 상태 관리 기능

- 수주 등록: 거래처 + 품목 1줄 이상(품목·수량·단가·VAT) + 희망 납기일 + 배송지 + 수신 연락처 + 알림 채널(SMS/이메일) + 메모.
    - 현장 담당자·생산라인은 등록하지 않음.
- 수주 등록 시 수주 등록 상태 ‘예정’.
- 계약금(선금) 입금이 확인되면 수주 등록 상태가 ‘확정’ (PG 웹훅)으로 되고 수주 상태는 생산대기 상태로 된다. 이후 작업지시서를 자동 등록한다.
- 정해진 일자까지 계약금이 없으면 수주·작업지시 취소는 수동.
- 수주 상태와 작업지시 상태는 분리하여 관리한다.
- 거래처·생산품목 선택 시 관련 필드 자동입력.
- 수량·단가·VAT 포함 여부 기준 총액 자동 산정.
- 수주 상태 관리: 대기 → 생산대기 → 생산중 → 포장중 → 포장완료 → 배송중 → 완료
    - 대기: 수주 정보 수정 및 취소 (수주 작성 후 입금 전)
    - 생산 보류: 기기 점검 및 고장시 (수동)
    - 생산대기: 선금 완료 된 상태 (자동) - 작업지시서 작성 후 생산 시작/중지 버튼
    - 생산중: 수량, 단가, 납기일 수정 허용 여부 (수동)
    - 포장중: 생산 완료 버튼 클릭시, 가공 완료된 제품을 포장 시 상태 (수동)
    - 포장완료: 포장 완료 후 배송 기사가 오기 전까지 대기하는 상태 (수동)
    - 배송중: 배송지 수정 허용 여부
    - 완료: 일반 직원 수정 제한
- 상태 변경 이력(이전 상태, 이후 상태, 시각, 처리자) 저장.
- 수주 목록 검색·필터 (상태, 납기, 거래처, 입금 여부 등).
- 수주 상세 조회.
- 납기 가능일 계산은 라인 미배정 기준으로 일자별 공장 생산량을 계산하여 정함. (납기일 = 생산완료예정일 + 2일)

### 1.2.5 입금 관리 기능

- PG사 (결제대행사)가 제공하는 실시간 계좌이체 및 무통장 입금용 가상계좌 발급 API 연동.
- PG사의 입금완료 웹훅 콜백 API를 수신하여 수주건의 입금 상태를 자동으로 업데이트
  (미입금 → 부분입금(선입금) → 입금완료(후입금)).
- 입금 완료 시 입금 시각·결제 승인번호 저장.
- 입금 상태와 수주 진행 상태(대기~완료)는 독립적으로 관리.

### 1.2.6 배송 알림 기능

- 배송 시작(상태: 배송중) 시 SMS 또는 메신저로 거래처에게 발송.
- 알림 발송 성공·실패 이력 저장.
- 알림 중복 발송 방지.
- 택배사 배송조회 API 연동.
- 택배사 선택 및 운송장 번호 입력 시 외부 배송 조회 API와 연동.

### 1.2.7 통계 및 대시보드 기능

- 수주 건수, 생산량, 납기 이행률, 품목별 분포 시각화.
- 상태별 파이프라인 요약 (대기 / 생산중 / 배송중 / 완료 건수).
- 납기 임박·지연 표시, 미입금 요약, 납기·출고 캘린더 뷰.
- **AI 기반 사업 리스크 관리:** 수주·생산·납기·입금 데이터를 분석하여 납기 지연 및 미입금 위험을 탐지하고, 예상 매출과 위험 요인별 대응 방안을 대화형 AI 비서를 통해 제공한다.

### 1.2.8 생산 라인 및 작업 할당 관리 기능

- **생산 라인 등록 및 관리**: 공장 내 생산 라인(예: 1라인, 2라인 등) 상태 및 가동 현황 관리.
    - 전체 생산라인 현황 페이지
    - 최고관리자만 신규 라인 등록 페이지 및 라인 정보 수정 가능
    - 현장 관리자는 라인 상태(가동가능/가동 중/점검 중/고장) 관리
    - 라인별 상세 정보 조회
- **수주건 라인 할당**:
    - 생산대기 상태의 작업지시서를 현장 담당자가 확인하고, 생산 가능한 라인을 선택하여 배정.
    - 배정 조건: 다른 작업에 배정되지 않은 가동 가능 라인.
    - 라인 배정 후 작업지시서에 생산라인 정보를 저장하고, 생산 시작 버튼을 통해 작업 상태를 생산중으로 변경.
- **작업자(직원) 일 할당 및 담당자 배치**:
    - 생산 시작 시 배정한 라인을 기준으로 하되, 설비 고장 등 현장 상황 발생 시 현장 담당자가 작업지시서를 수정하여 다른 라인으로 변경할 수 있도록 함.
    - 라인별로 현재 작업 중인 수주목록 및 담당 직원 현황을 실시간 시각화.
    - 작업자별 작업 진행 상황 업데이트 및 작업 완료 보고 기능.

## 1.3 비기능 요구사항 및 기술 스택

### 1.3.1 시스템 아키텍처 및 기술 스택

- 백엔드 코어: Java 25, Spring Boot 4.x, Gradle 9.x
- 영속성 및 ORM: Spring Data JPA, Hibernate, OpenFeign, QueryDSL 7.x
- 데이터베이스: MySQL 9.x (9.7, 운영)
- 보안 및 인증: Spring Security 6.x, JJWT
- 클라우드 인프라: AWS EC2, RDS (MySQL), S3 (미디어 콘텐츠), CloudFront
- 컨테이너 및 CI/CD: Docker, Docker Compose, GitHub Actions 기반 CI/CD 배포 자동화 파이프라인
- 프론트엔드: React 19.x, TypeScript 6.x, Vite 8.x, Tailwind CSS 4.x, Zustand 5.x, Axios
- AI 어시스턴트: 추후 작성

### 1.3.2 데이터 정합성 및 쿼리 성능 최적화

- 선언적 트랜잭션 관리: 수주·생산계획·생산실적 등록 및 수정 시 `@Transactional`을 활용하여 연관 데이터의 원자성과 정합성 확보.
- JPA 쿼리 최적화: Fetch Join과 DTO 직접 조회를 활용하여 N+1 문제를 방지하고 불필요한 데이터 조회 최소화.
- 데이터 무결성 보장: 외래키(FK), UNIQUE 및 NOT NULL 제약조건을 활용하여 데이터 중복과 참조 무결성 위반 방지.
- 인덱스 최적화: 수주번호, 생산일자, 진행 상태 등 주요 검색 조건에 인덱스를 적용하여 조회 성능 개선.
