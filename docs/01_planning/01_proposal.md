# PRODFLOW — 내부 생산·수주 관리 플랫폼 기획서

PRODFLOW는 휴대폰 케이스 생산시설의 임직원을 위한 내부 생산·수주 관리 플랫폼이다. **견적 → 수주 → 계약금 → 작업지시 → 포장 → 출고 → 배송 → 잔금**으로 이어지는 업무 흐름을 통합 관리하고,
처리 상태와 이력을 기록한다.

## 1. 기획 개요

### 1.1 배경·목적

견적·수주·납기·출고 업무를 수기와 유선으로 처리하는 과정에서는 정보 누락과 업무 혼선이 발생할 수 있다. PRODFLOW는 임직원 전용 내부 전산화 시스템으로, 등록 검증, 상태 이력 관리, 조회·집계 기능을 통합
제공한다.

### 1.2 사용자·역할

외부 회원가입과 거래처 전용 화면은 제공하지 않는다. 사용자 계정은 최고 관리자가 생성한다.

| 역할        | 코드                   | 주요 업무                       |
|-----------|----------------------|-----------------------------|
| 최고 관리자    | `SUPER_ADMIN`        | 계정·기준정보·라인·수주·생산 전반         |
| 수주 관리자    | `ORDER_MANAGER`      | 견적·수주·거래처·품목(허용 범위)·라인·담당자  |
| 생산 현장 관리자 | `PRODUCTION_MANAGER` | 배정 작업 시작·정지·포장, 라인 가동·점검·고장 |
| 업무 조회 담당  | `INQUIRY_MANAGER`    | 조회만 (등록·수정·상태 변경 없음)        |

### 1.3 기대 효과

- 견적·수주 정보를 등록 시점의 스냅샷으로 보존한다.
- 계약금 입금 전에는 생산 시작을 제한한다.
- 배송 완료와 잔금 입금을 독립적으로 관리한다.
- 대시보드는 저장된 계획과 상태만 집계한다.

## 2. 전체 업무 흐름

1. **견적 작성·발송**: 거래처와 품목을 선택하고 납기를 계산한다. PDF 확인 후 발송을 확정하면 `SENT` 상태로 전환한다. 견적 작성 단계에서는 생산 용량을 예약하지 않는다.
2. **승인**: 직원이 견적의 승인·거절·취소 결과를 반영한다.
3. **수주 등록**: 승인된 견적을 기준으로 수주를 등록한다. 저장 시 초기 상태는 `WAITING`(예정)이다.
4. **계약금 안내**: 수주 상세 화면에서 가상계좌를 발급하고 이메일로 안내한다.
5. **계약금 입금완료**: 수주를 생산대기(`CONFIRMED`) 상태로 전환하고 작업지시와 생산계획을 생성한다.
6. **생산 → 포장**: 모든 작업이 `PACK_DONE` 상태가 되면 포장중 탭의 조회 대상에 포함한다.
7. **출고대기**: 직원이 수주를 `READY_TO_SHIP` 상태로 전환한다.
8. **운송장 등록**: 운송장 저장, 잔금 계좌 준비, 이메일 전송을 순차적으로 처리한 뒤 출고를 확정하고 `SHIPPING` 상태로 전환한다.
9. **배송 완료**: 수주를 `COMPLETED` 상태로 전환한다. 잔금 입금은 별도로 처리한다.

## 3. 주요 기능

### 3.1 계정·인증

- 로그인 시 Access Token과 Refresh Token을 발급한다. Refresh Token은 해시값만 저장한다.
- 임시 비밀번호를 사용하는 계정은 비밀번호 변경 후 업무 기능을 이용할 수 있다.
- 계정 삭제는 Soft Delete 방식으로 처리한다.
- API에서도 사용자 권한을 검증한다.

### 3.2 거래처

- 거래처 등록·수정은 최고 관리자와 수주 관리자가 수행한다.
- 거래처 등록 시 도로명 주소 검색을 지원한다.
- 엑셀 파일을 통한 거래처 일괄 등록을 지원한다.
- 견적 작성 시 거래처 자동완성을 지원한다.
    - 거래처가 등록되어 있지 않으면 견적 저장 시 함께 생성한다. 동일한 회사명이 있으면 기존 거래처 정보를 불러온다.
- 수주에는 등록 시점의 거래처 정보를 스냅샷으로 저장한다.

### 3.3 생산품목·도면

- 생산품목은 모델코드, 제품명, 기종, 설명, 기준 단가로 구성한다.
- 상태는 `AVAILABLE(생산가능)` / `DISCONTINUED(생산중지)`이다.
- 기종은 기존 기종을 선택하거나 신규 기종명을 입력한다. 두 입력 방식의 동시 사용은 허용하지 않는다.
- 목록 및 검색 결과에 페이지네이션을 적용한다.
- 도면은 별도로 업로드한다.
    - 현재 도면은 유효기간이 10분인 Presigned URL로 제공한다.
    - 응답에 `objectKey`는 노출하지 않는다.
    - 도면 삭제 시 `replaced_at`을 기록하고 S3 객체를 삭제한다.

### 3.4 견적

- 거래처와 품목별 수량·단가를 입력하여 견적서를 작성한다. 
- 생산능력을 기준으로 예상 납기를 산정하고, 견적서를 PDF로 확인·발송한다. 
- 거래처의 승인·거절 결과를 기록하고, 승인된 견적을 수주로 연결한다.

### 3.5 수주

- 승인된 견적 1건당 수주는 최대 1건만 등록할 수 있다.
- 품목별 수주 수량은 100개 이상이며, 견적 수량을 초과할 수 없다.
- 계약금은 총액의 50%로 산정하고 원 단위로 내림한다.
- 계약금 마감일은 일반 주문의 경우 등록일 +3일, 당일 착수 요청의 경우 등록 당일로 설정한다.
- 계약금 발급과 수주 저장은 별도 API로 처리한다.

### 3.6 납기

- 가동 라인의 생산능력을 합산하고, 수주 등록 순서에 따라 생산 물량을 우선 배정한다.
- 일반 주문의 생산 시작 기준일은 견적의 경우 오늘 +3일, 수주의 경우 계약금 마감일이다. 당일 착수 요청은 오늘부터 생산 가능한지 계산하여 기존 일정 컬럼에 저장한다. 수주 등록 시 당일 착수가 불가능하면 일반
  일정으로 전환하고, 협의한 날짜로 등록할 수 있다.
- 주말과 공휴일은 제외한다.
- 생산 완료 후 3영업일을 확보하여 납기 준수 가능 여부를 계산한다.

### 3.7 수주 상태

- 대기(`WAITING`) → 생산대기(`CONFIRMED`) → 생산중 / 보류 → 포장중 → 출고대기 → 배송중 → 완료
- 입금 상태(`UNPAID` / `PARTIALLY_PAID` / `PAID`)는 수주 진행 상태와 독립적으로 관리한다.

### 3.8 결제·입금

- 입금은 PortOne 가상계좌 웹훅 또는 수동입금으로 처리한다.
- 계약금이 `PAID` 상태가 되면 수주를 생산대기로 전환하고 작업지시를 생성한다.
- 잔금 결제는 운송장 등록 시 준비한다.

### 3.9 작업지시·라인

- 계약금 입금 확인 후 작업지시와 일자별 생산계획을 생성한다.
- 작업 상태는 `PREPARE` → `PRODUCE` → `PACK` → `PACK_DONE` 순으로 진행하며, `SUSPEND`(일시정지)와 `HALT`(생산중지) 상태를 별도로 관리한다.
- 라인 상태는 `AVAILABLE` / `OPERATING` / `INSPECTION` / `BROKEN`이다.

### 3.10 포장·배송

- 모든 작업이 `PACK_DONE` 상태가 되면 출고대기 → 운송장 등록 → 배송중 순으로 진행한다.
- 운송장은 수주당 1건으로 제한하며, 택배사와 운송장 번호의 조합은 중복을 허용하지 않는다.
- 배송조회 실패 시 운송장과 수주의 상태를 변경하지 않는다.
- 조회 탭은 `PACKING(포장 끝)` / `READY_TO_SHIP(출고 대기)` / `SHIPPING(배송중)` / `BALANCE(잔금 대기)`로 구분한다.
    - 각 탭에서 수주의 현재 상황에 해당하는 목록을 조회한다.

### 3.11 대시보드·내부 알림

- KPI는 계획 수량과 상태를 기준으로 집계한다.
- 납기 알림과 라인 알림은 내부 직원에게만 제공한다.
- 생산 일정 캘린더에서 주간·월간 생산 일정을 조회한다.

### 3.12 AI

- 대화방 기반으로 대화 이력을 관리하며, Gemini / Groq 모델을 선택하여 질문할 수 있다.
- 자연어 업무 질문을 SQL로 변환하고, MCP 도구를 통해 데이터베이스를 조회한다.
- SQL 안전성 검증과 읽기 전용 DB 계정으로 데이터 변경을 방지한다.
- 조회 결과를 사용자에게 자연어 및 표 형식으로 제공한다.
