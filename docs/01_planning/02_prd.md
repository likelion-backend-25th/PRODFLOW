## 1.3 비기능 요구사항 및 CI/CD 자동화

### 1.3.1 데이터 정합성 및 보안 요구사항

- 결제 검증 원자성: 결제 사전 검증(결제 대기 레코드 생성)과 사후 검증(PG사 실결제 금액 대조 및 수강권 발급)은 단일 트랜잭션(@Transactional) 내에서 처리되어 데이터 불일치 차단.
- 인증/인가 무상태성: Spring Security와 JJWT를 활용하여 서버 세션 의존성을 제거하고, 토큰 탈취 방지를 위한 RTR(Refresh Token Rotation) 체계 필수 적용.
- 입력값 검증: 컨트롤러 계층 진입 시 Spring Boot Validation(@Valid, @NotNull, @Size 등)을 통한 사전 유효성 검증 및 전역 예외 처리기(
  @RestControllerAdvice) 표준 응답 반환.

### 1.3.2 성능 및 대용량 데이터 처리 요구사항

- 쿼리 최적화: 강좌 상세 및 커리큘럼 조회 시 JPA Fetch Join을 적용하여 N+1 문제 원천 차단, 복합 검색 쿼리는 QueryDSL 기반 인덱스 친화적 동적 쿼리 구성.
- 대용량 배치 프로세싱: Spring Batch 기반 대용량 일괄(Chunk) 프로세싱을 도입하여 수만 건의 수강 만료 및 정산 데이터를 페이징 단위(예: 500건)로 안전하게 처리.

### 1.3.3 GitHub Actions 기반 CI/CD 배포 자동화 파이프라인

- 지속적 통합 (CI Pipeline):
    - main 및 develop 브랜치 대상 Pull Request(PR) 및 Push 이벤트 감지.
    - JDK 및 Gradle 캐싱 환경 설정.
    - Gradle 컴파일 및 단위/통합 테스트(JUnit5) 자동 실행.
    - 테스트 실패 시 배포 파이프라인 즉시 중단 및 GitHub PR 피드백 표시.
- 지속적 배포 (CD Pipeline):
    - CI 파이프라인 통과 후 Spring Boot 애플리케이션 JAR 빌드.
    - Docker 멀티 스테이지 빌드를 통한 경량화된 컨테이너 이미지 자동 생성.
    - AWS EC2 인스턴스로 SSH 원격 접속 및 Docker Compose 기반 신규 컨테이너 무중단 롤링 배포 수행.
    - Nginx 헬스체크 검증 후 배포 완료 알림 전송.
