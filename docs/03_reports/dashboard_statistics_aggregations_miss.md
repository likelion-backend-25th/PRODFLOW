## 1. 문제 발생

- 문제 유형
    - JPA 집계 쿼리
    - 날짜 조건 및 통계 데이터 조회
- 현상 설명
    - 통계 데이터가 DB에 존재하는데 대시보드 일부 항목이 `0`으로 표시되는 문제가 발생함.
    - 대시보드에서 선택한 월과 실제 통계 조회에 사용되는 기간이 일치하지 않아 월간 생산량 및 품목별 통계가 정상적으로 표시되지 않는 현상이 발생함.
    - 통계마다 조회 대상 엔티티와 집계 기준이 달라 데이터 조회 조건을 일관성 있게 관리할 필요가 있었음.

---

## 2. 원인 분석

- 대시보드 통계는 하나의 테이블이 아닌 여러 엔티티를 기준으로 데이터를 집계하는 구조였음.
- 각 통계의 데이터 출처와 조회 조건이 달라 통계별 조회 로직을 구분해서 확인할 필요가 있었음.

1. **통계별 엔티티 분리**

- 수주 건수는 `CustomerOrder`를 기준으로 조회함.
- 생산 계획량은 `ProductionPlan`을 기준으로 조회함.
- 생산 완료량은 `WorkOrder`를 기준으로 조회함.
- 납기 현황은 수주 및 배송 관련 엔티티를 기준으로 조회함.
- 통계마다 데이터 출처와 집계 기준이 달라 동일한 조회 조건을 적용하기 어려웠음.

2. **월간 조회 조건 확인**

- 대시보드에서 선택한 월과 API에 전달되는 `from`, `to` 날짜 조건을 확인함.
- 프론트엔드에서 선택한 월과 백엔드 Repository의 조회 기간이 일치하지 않으면 해당 기간의 데이터가 집계에서 누락될 수 있었음.
- 월별 통계마다 날짜 필드와 조회 조건이 올바르게 적용되는지 확인할 필요가 있었음.

3. **집계 기준 불일치**

- 계획 생산량과 생산 완료량은 서로 다른 엔티티와 상태 조건을 기준으로 집계해야 함.
- 수주 건수나 작업지시 건수를 기준으로 생산 수량을 계산하면 실제 집계 대상 수량과 차이가 발생할 수 있었음.

---

## 3. 해결 방법

- 통계별 데이터 출처와 조회 기간을 구분하고, 실제 집계 기준에 맞게 JPA 조회 로직을 점검함.

1. **통계별 조회 엔티티 구분**

- 수주 통계는 `CustomerOrder`를 기준으로 조회하도록 확인함.
- 계획 생산량은 `ProductionPlan.plannedQuantity`를 기준으로 집계함.
- 납기 통계는 수주 납기일과 배송 완료 정보를 기준으로 조회하도록 확인함.
- 통계별로 적절한 엔티티와 집계 기준을 적용하도록 조회 로직을 점검함.

2. **날짜 조회 조건 통일**

- API에서 전달받은 `from`, `to` 파라미터를 기준으로 조회 기간을 설정함.
- 선택한 월에 해당하는 데이터만 집계되도록 날짜 조건을 확인함.
- 프론트엔드의 월 선택 값과 백엔드에 전달되는 조회 기간이 일치하는지 점검함.

3. **집계 결과 검증**

- Repository 조회 결과와 실제 DB 데이터를 비교함.
- API 응답 데이터와 대시보드에 표시되는 값이 일치하는지 확인함.
- 통계별 집계 대상 엔티티와 상태 조건을 점검함.

---

## 4. 배운점

- JPA를 활용한 통계 기능은 단순히 데이터를 조회하는 것이 아니라 어떤 엔티티를 기준으로 어떤 조건으로 집계할지 정의하는 것이 중요함.
- 계획 수량과 생산 완료 수량처럼 의미가 다른 데이터는 각각 적절한 엔티티와 상태 조건을 기준으로 집계해야 함.
- 날짜 조건이 필요한 통계는 프론트엔드와 백엔드가 동일한 조회 기간을 사용해야 데이터 누락을 방지할 수 있음.
- 여러 엔티티에 분산된 데이터를 하나의 대시보드에서 제공하려면 DB 구조와 엔티티 간 연관관계를 정확하게 이해해야 함.
