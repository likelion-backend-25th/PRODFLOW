# 화면 설계서 (UI Wireframe)

## 1. 서비스 화면 구성 개요

ProdFlow는 생산시설의 수주, 생산, 입금, 포장, 출고, 배송 조회를 한 시스템에서 처리하는 내부 임직원 전용 SPA(Single Page Application)입니다. 외부 회원가입 화면은 없고, 로그인한
직원의 역할(최고 관리자 / 수주 관리자 / 생산 현장 관리자 / 업무 조회 담당자)에 따라 메뉴와 버튼이 다르게 보입니다.

### 1.1 주요 화면 목록

- 로그인 화면 (`/login`)
- 대시보드 화면 (`/dashboard`)
- 내 정보 화면 (`/me`)
- 계정 관리 화면 (`/admin/users`, `/admin/users/new`, `/admin/users/{userId}`)
- 거래처 관리 화면 (`/clients`, `/clients/new`, `/clients/{clientId}`)
- 생산품목 관리 화면 (`/products`, `/products/new`, `/products/{productId}`)
- 견적서 목록 화면 (`/quotations`)
- 견적서 등록 화면 (`/quotations/new`)
- 견적서 상세 화면 (`/quotations/{quotationId}`)
- 수주 목록 화면 (`/orders`)
- 수주 등록 화면 (`/orders/new?quotationId={quotationId}`)
- 수주 상세 화면 (`/orders/{customerOrderId}`)
- 입금 관리 화면 (`/payments`)
- 작업지시서 관리 화면 (`/work-orders`, `/work-orders/{workOrderId}`)
- 생산라인 관리 화면 (`/lines`, `/lines/new`, `/lines/{lineId}`)
- 생산 일정 캘린더 화면 (`/production/calendar`)
- 배송 관리 화면 (`/shipments`)
- AI 챗봇 화면 (`/ai`)

## 2. 로그인 화면**(`/login`)**

<img src="../images/login.png" width="500" alt="로그인 화면">

- **출력 데이터 항목 (Output Data):**
    - 서비스 로고 및 내부 전용 서비스 안내 문구
    - 아이디(이메일) 입력 필드
    - 비밀번호 입력 필드
    - 아이디 저장 체크박스
    - 로그인 버튼
    - 로그인 문제 안내 링크
    - 최초 이용자 안내 문구
    - 시스템 담당자 안내 정보
- **입력 데이터 및 검증 규칙 (Input Data & Validation):**
    - **아이디(이메일)**
        - 필수 입력
        - 발급된 사내 계정의 이메일 입력
        - 이메일 형식 검증
    - **비밀번호**
        - 필수 입력
        - 입력값은 마스킹하여 표시
        - 보기 아이콘을 통해 입력값 표시 여부 변경 가능
    - 이메일 또는 비밀번호가 일치하지 않으면 공통 오류 메시지 표시
    - 비활성(`INACTIVE`) 또는 삭제(`DELETED`) 상태의 계정은 로그인 불가
    - 활성(`ACTIVE`) 상태의 계정만 로그인 가능
    - 최초 임시 비밀번호 사용 여부에 따라 비밀번호 변경 필요 여부 확인
    - 새 비밀번호는 8~20자로 입력
    - 새 비밀번호와 비밀번호 확인 값이 일치해야 함
    - 기존 임시 비밀번호와 다른 비밀번호로 변경해야 함
- **화면 제어 및 동작 규칙 (Behavior Rules):**
    - 외부 회원가입 기능은 제공하지 않는다.
    - 계정은 최고 관리자가 계정 관리 화면에서 등록 및 발급한다.
    - 로그인 버튼 클릭 시 이메일과 비밀번호를 서버에서 검증한다.
    - 로그인 성공 시 Access Token은 응답 본문으로 반환하고 Refresh Token은 HttpOnly Cookie로 발급한다.
    - 로그인 성공 시 마지막 로그인 일시(`last_login_at`)를 갱신한다.
    - `mustChangePassword = TRUE`인 경우 최초 비밀번호 변경 화면으로 이동한다.
    - 최초 비밀번호 변경 전에는 일반 업무 API 접근을 제한한다.
    - `mustChangePassword = FALSE`인 경우 대시보드(`/dashboard`)로 이동한다.
    - 최초 비밀번호 변경은 `POST /api/v1/auth/change-password` API를 사용한다.
    - 비밀번호 변경 성공 시 기존 Refresh Token을 삭제하고 쿠키를 만료 처리하며, 다시 로그인하도록 안내한다.
    - 아이디 저장 체크 시 브라우저에 아이디를 저장하고 다음 로그인 화면에 표시한다.
    - Access Token 만료 시 Refresh Token 쿠키를 이용해 재발급한다.
    - Refresh Token 재발급 성공 시 새로운 Access Token을 반환하고 Refresh Token 쿠키를 갱신한다.
    - Refresh Token이 만료되거나 유효하지 않으면 로그인 화면으로 이동한다.
    - 로그인 문제 안내 링크 클릭 시 시스템 담당자 문의 안내를 제공한다.

### **2.1 비밀번호 변경 화면(`/change-password`)**

<img src="../images/change_password.png" width="500" alt="비밀번호 변경 화면">

- **출력 데이터 항목 (Output Data)**
    - 비밀번호 변경 안내 문구
    - 임시 비밀번호 입력 필드
    - 새 비밀번호 입력 필드
    - 비밀번호 설정 기준 (8~20자)
    - 새 비밀번호 확인 입력 필드
    - 비밀번호 일치 여부 표시
    - 비밀번호 변경 버튼
- **입력 데이터 및 검증 규칙 (Input Data & Validation)**
    - **임시 비밀번호**
        - 필수 입력
        - 현재 계정에 발급된 임시 비밀번호 입력
        - 입력값 마스킹 처리
    - **새 비밀번호**
        - 필수 입력
        - 8자 이상 20자 이하
        - 기존 임시 비밀번호와 동일한 비밀번호 사용 불가
    - **새 비밀번호 확인**
        - 필수 입력
        - 새 비밀번호와 동일해야 함
    - 비밀번호 조건 및 일치 여부를 입력 중 표시한다.
- **화면 제어 및 동작 규칙 (Behavior Rules)**
    - 로그인 성공 후 `mustChangePassword = TRUE`인 사용자만 해당 화면으로 이동한다.
    - 비밀번호 변경 전까지 일반 업무 API 접근을 제한한다.
    - URL을 직접 입력해 다른 업무 화면에 접근하더라도 서버에서 접근을 제한한다.
    - 임시 비밀번호와 새 비밀번호를 서버에서 검증한다.
    - 모든 입력값이 유효하고 비밀번호 확인이 일치하면 변경 버튼을 활성화한다.
    - 비밀번호 변경 요청은 `POST /api/v1/auth/change-password` API를 사용한다.
    - 변경 성공 시 새 비밀번호를 암호화하여 저장하고 `mustChangePassword`를 `FALSE`로 변경한다.
    - 기존 Refresh Token을 삭제하고 쿠키를 만료 처리한다.
    - 변경 완료 후 로그인 화면으로 이동하며, 재로그인 성공 시 대시보드(`/dashboard`)로 이동한다.

## 3. 대시보드 화면 (`/dashboard`)

<img src="../images/dashboard.png" width="500" alt="대시보드 화면">

- 출력 데이터 항목 (Output Data):
    - 상단 안내 영역
        - 현재 날짜 및 기준 월
        - 지연 수주 및 미입금 등 주요 업무 안내 메시지
        - 전체 수주 확인 바로가기
    - 핵심 지표(KPI)
        - 이번 달 수주 건수 및 전월 대비 증감
        - 이번 달 누적 생산량 및 생산 계획 대비 진행률
        - 납기 이행률 및 납기 지연 건수
        - 진행 중인 수주 건수 및 상태별 건수
    - 생산량 통계
        - 조회 월 기준 주차별 생산 계획 수량 및 완료 수량
        - 생산 계획과 완료 수량을 구분하여 그래프로 표시
    - 품목별 생산
        - 조회 월 기준 품목별 생산 계획 수량 및 비중
        - 상위 품목의 제품명, 생산 수량 및 비율
    - 주간 생산 일정
        - 조회 주차 및 날짜별 생산 예정 수주
        - 작업지시 번호, 수주번호, 거래처명, 생산품목
        - 작업지시 수 및 생산 예정 수량
        - 해당 날짜의 생산 예정 수량 및 가용 생산량
        - 작업 상태 및 생산 일정 요약
    - 납기 위험 수주
        - 수주번호
        - 거래처명 및 생산품목
        - 납기일 및 위험 발생 기준일
        - 작업 상태
        - 위험 사유(납기 임박, 납기 지연, 기기 고장으로 인한 생산 일정 지연 등)
        - 입금 상태
        - 알림 전송 여부 및 알림 전송 기능
    - 알림 요약
        - 읽지 않은 알림 건수
        - 최근 알림 목록
        - 알림 유형 및 메시지
        - 관련 수주번호 및 거래처명
        - 발생 시각 및 읽음 여부
    - 사용자 정보
        - 로그인 사용자명 및 역할
        - 알림 확인 및 사용자 메뉴
- 화면 제어 및 동작 규칙 (Behavior Rules):
    - 모든 역할이 조회 가능.
    - 조회 기간 변경 시 핵심 지표, 생산량 통계 등 기간에 영향 받는 데이터가 갱신
    - 핵심 지표는 조회 기간과 집계 기준에 맞게 표시
    - 생산량은 작업지시 목표 수량 및 날짜별 생산계획 수량을 기준으로 집계하며, 화면에 집계 기준을 표시
    - 상태별 수주 현황 클릭시 해당 상태로 필터링 된 수주 목록으로 이동
    - 주간 생산 일정은 이전/다음 날짜 이동 및 오늘 기준 조회를 지원
    - 날짜별 생산 업무 카드 클릭시 선택한 수주의 생산 일정 상세 사이드 패널 표시
    - 날짜별 생산 업무 카드가 여러 건인 경우 더보기 기능을 통해 추가 일정을 확인
    - 납기 위험 수주 목록의 행 또는 상세보기 버튼 클릭 시 해당 수주의 상세 사이드 패널 표시
    - 납기 위험 수주 목록에서 선택한 수주와 생산 일정에서 선택한 수주가 동일한 경우 동일한 수주 상세 정보를 표시
    - 납기 위험 수주 목록의 알림 전송 기능 클릭 시 해당 수주 납기 알림을 전송
    - 알림 전송 시 해당 수주의 담당 직원에게 전달
    - 알림 아이콘 클릭 시 알림 드롭다운 표시
    - 알림 드롭다운에서 전체 및 읽지 않음 기준으로 알림 목록 조회
    - 전체 읽음 버튼 클릭시 해당 사용자의 읽지 않은 알림을 모두 읽음 상태로
    - 납기 위험 수주에서 수주 목록을 누르면 수주 목록 화면으로 이동
    - 사용자 역할에 따라 조회 가능한 데이터 범위와 실행 가능한 기능을 구분하며, 권한 없는 기능은 제한

### 3.1 대시보드 : 생산 일정 상세

- 출력 데이터 항목 (Output Data):
    - 헤더 영역
        - 생산 일정 상세 제목
        - 작업지시 번호
        - 작업지시 상태 및 뱃지
        - 닫기 버튼
    - 수주 및 생산 정보
        - 수주 번호
        - 거래처명
        - 생산품목
        - 생산 수량
        - 생산 시작 예정일
        - 납기일
        - 수주 진행 상태
        - 담당자
        - 비고
    - 하단 기능 영역
        - 수주 상세보기 버튼
- 화면 제어 및 동작 규칙 (Behavior Rules):
    - 패널 오픈 :
        - 대시보드 내 ‘이번 주 생산 일정’의 날짜별 업무 카드 클릭
        - ‘납기 위험 수주’ 목록의 행이나 상세보기 버튼 클릭
    - 선택한 수주의 정보를 우측 사이드 패널로 표시
    - 생산 일정에서 선택한 수주와 납기 위험 수주에서 선택한 수주는 동일한 상세 정보 구조를 사용
    - 패널 내부 스크롤을 통해 상세 정보 확인
    - 닫기 버튼 클릭시 사이드 패널을 닫음
    - 사이드 패널 외부 영역 클릭 또는 ESC 입력 시 패널 닫음
    - 다른 생산 일정 또는 납기 위험 수주를 선택하면 패널을 유지한 상태로 선택한 수주의 상세 정보로 변경
    - 수주 상세보기 버튼 클릭 시 해당 수주의 상세 화면으로 이동
    - 상세 정보는 조회 목적으로 제공하고 사이드 패널에서 수정 불가

#### 3.2 대시보드 알림 드롭다운

- 출력 데이터 항목 (Output Data):
    - 헤더 영역
        - 알림 제목
        - 읽지 않은 알림 건수
        - 전체 읽음 버튼
    - 알림 목록
        - 알림 유형
        - 알림 제목 및 메시지
        - 관련 수주번호 또는 생산라인 정보
        - 발생 시각
        - 읽음 여부
    - 알림 유형 및 내용 예시
        - 납기 임박 : 담당 수주의 납기일이 3일 남았을 경우 알림
        - 납기 지연 : 담당 수주의 납기일이 초과 되었을 때 알림
        - 생산라인 상태 변경 : 생산라인의 가동, 점검, 고장 등 상태 변경 알림
- 화면 제어 및 동작 규칙 (Behavior Rules):
    - 상단 알림 아이콘 클릭 시 드롭다운 표시
    - 드롭다운에서 전체 및 읽지 않음 필터를 선택하여 알림 목록 조회
    - 알림 목록은 로그인한 사용자의 수신 알림을 기준으로 표시
    - 알림 클릭 시 해당 알림은 읽음 상태 처리
    - 수주 관련 알림 클릭 시 해당 수주 정보로 이동
    - 전체 읽음 버튼 클릭 시 로그인 사용자의 미확인 알림을 모두 읽음 처리
    - 알림 읽음 처리 후 읽지 않은 알림 건수 갱신
    - 알림이 없는 경우 알림이 없다는 문구 표시
    - 다른 화면 영역을 클릭하거나 드롭다운 외부를 클릭하면 드롭다운을 닫음

    - **계정 추가 모달**
        - 이름, 이메일, 전화번호 입력
        - 역할 선택

    - **페이지네이션**
        - 페이지당 표시 건수
        - 현재 페이지 및 페이지 이동 버튼
        - 전체 조회 건수
- **입력 데이터 및 검증 규칙 (Input Data & Validation):**
    - 검색어는 이름, 이메일, 전화번호를 기준으로 검색 가능
    - 검색어 앞뒤 공백 제거 및 최대 100자 제한
    - 검색 조건이 없으면 사용 및 비활성 계정 전체 조회
    - 상태 필터는 `ACTIVE`, `INACTIVE`만 허용
    - 삭제된 계정(`DELETED`)은 목록에서 제외
    - 계정 등록 시 이름, 이메일, 전화번호, 역할 필수 입력
    - 이메일 형식 및 중복 여부 확인
    - 임시 비밀번호는 12자리이며 영문 대문자, 소문자, 숫자, 특수문자를 각각 포함
    - 임시 비밀번호의 허용 특수문자는 `! @ # $ % & * ?`
    - 계정 수정 시 이메일 중복 여부 확인
    - 계정 상태는 `ACTIVE`, `INACTIVE`만 변경 가능
    - 임시 비밀번호 재발급 시 기존과 동일한 비밀번호 규칙 적용
    - 삭제된 계정은 수정할 수 없음
- **화면 제어 및 동작 규칙 (Behavior Rules)**
    - 최고 관리자(`SUPER_ADMIN`)만 계정 관리 화면에 접근할 수 있다.
    - 다른 역할의 사용자가 직접 URL로 접근하면 `403 Forbidden`을 반환한다.
    - 화면 진입 시 계정 현황 통계와 계정 목록 조회
    - 통계는 검색 및 필터 조건과 관계없이 전체 계정을 기준으로 집계하며 `DELETED` 계정은 제외
    - 계정 목록의 행 클릭 시 선택한 계정의 상세 정보를 우측 패널에 표시
    - 계정 추가 버튼 클릭 시 현재 `/admin/users` 화면 위에 등록 모달 표시
    - 계정 정보 수정 버튼 클릭 시 현재 화면 위에 수정 모달 표시
    - 모달을 표시하더라도 페이지 URL은 `/admin/users` 유지
    - 신규 계정 등록 시 프론트엔드에서 생성한 임시 비밀번호를 전달하고 서버에서 암호화하여 저장
    - 신규 계정은 `ACTIVE` 상태 및 `mustChangePassword = TRUE`로 생성
    - 임시 비밀번호 재발급 시 다음 로그인에서 비밀번호 변경 필요
    - 계정 상태는 사용(`ACTIVE`), 비활성(`INACTIVE`), 삭제(`DELETED`)로 관리
    - 비활성 계정은 로그인 및 서비스 접근 제한
    - 계정 삭제 시 실제 데이터를 삭제하지 않고 `DELETED` 상태로 변경하며 삭제 일시 기록
    - 삭제된 계정의 Refresh Token 제거
    - 삭제된 계정은 일반 목록에서 제외하며 화면에서 복구 기능 제공하지 않음
    - 이메일, 역할, 상태 또는 비밀번호 변경 시 기존 Refresh Token 폐기
    - 계정 추가, 수정, 삭제 완료 시 계정 목록과 현황 통계 갱신
    - 페이지 이동 및 표시 건수 변경 시 계정 목록 재조회

    - 임시 비밀번호 미발급 시 계정 등록을 제한한다.

    - 임시 비밀번호는 서버에서 BCrypt 방식으로 암호화하여 저장한다.
    - 신규 계정은 `ACTIVE` 상태 및 `mustChangePassword = TRUE`로 생성한다.

    - 닫기 버튼 또는 X 버튼 클릭 시 입력 내용을 저장하지 않고 모달을 닫는다.

- 출력 데이터 항목 (Output Data):
    - 상단: `워크스페이스 > 생산품목 관리 > 생산품목 등록`, 제목, `생산품목 목록으로`

    - 기종 추가 모달: 기종명, 취소·추가

- 입력 데이터 및 검증 규칙 (Input Data & Validation):

    - 기종: 기존 선택 또는 `기종 추가`로 신규 입력 후 선택
    - 기준 단가: 0보다 큰 정수, 부가세 별도. 변경해도 기존 견적·수주 단가는 유지
    - 파일: 파일당 100MB 이하, 여러 장 가능
- 화면 제어 및 동작 규칙 (Behavior Rules):
    - 목록으로·취소 → `/products`
    - `기종 추가` → 모달에서 추가 후 목록 반영·선택. 취소·X는 저장 없이 닫기
    - `생산품목 등록` → 수주 관리자·최고 관리자만. 성공 시 AVAILABLE, 목록으로 이동
    - 파일은 등록 후 업로드. 화면에 파일명만 표시

    - 날짜는 선택한 기준 날짜와 비교
    - `수주 대기`ON 시 상태는 승인으로 고정

    - `초기화`→ 검색어·상태·날짜·`수주 대기`해제

    - 품목 1개 이상. 동일 품목 중복 추가 불가. 수량 품목당 100개 이상. 단가는 품목 단가로 시작 후 수정 가능
    - 없는 품목은`신규 품목 등록`모달(모델코드·제품명·기종·설명·기준 단가)로 등록 후 줄 추가

    - `견적 발송`→ PDF 미리보기 후 발송. 성공 시 상태`SENT`. 단가는 유효기간 내만 승인 가능
    - 금액 요약은 넓은 화면에서 오른쪽에 고정

### 9.2 수주 등록 화면(`/orders/new`)

<img src="../images/order_regist.png" width="500" alt="수주 등록 화면">

    - `당일 착수 요청`, 납기 가능 여부 안내, 필요 시`납기`선택·`가장 빠른 날로`- 배송:`등록된 회사 주소로 배송`, 우편번호·`우편번호 찾기`, 도로명·상세, 수신자, 수령 연락처, 알림 채널, 업무
      메모
    - 오른쪽: 등록 직후 상태 안내, 일정(생산 시작·완료·등록할 납기), 금액(견적 총액·수주 총액·계약금 50%), 계약금 마감,`수주 등록`
- 입력 데이터 및 검증 규칙 (Input Data & Validation):
    - 승인 견적만. 이미 수주 있으면 기존 수주 안내. 취소 수주 연결 견적은 재사용 불가
    - 품목 추가·삭제·단가 변경 불가. 수량만 1개 이상·견적 수량 이하로 감소 가능
    - 견적 예상 납기 가능하면 날짜 선택 없음. 불가능하면 가장 빠른 날 이후만 선택
    - 배송지·수신자·수령 연락처 필수. 회사 주소 체크 시 등록 주소 없으면 등록 불가
    - 계약금 마감: 일반 등록일+3일, 당일 착수면 오늘. 직접 선택 불가
    - 수량 감소·납기 변경·당일 착수 해제 시 거래처 동의 체크 필수
- 화면 제어 및 동작 규칙 (Behavior Rules):
    - 수주 관리자·최고 관리자만 접근. 화면 닫으면 수주 미생성
    - `등록된 회사 주소로 배송`ON → 주소 자동 채움·수정 불가. OFF → 직접 입력
    - `당일 착수 요청`ON → 오늘부터 용량·계약금 오늘 마감. OFF → 일반 일정

    - 계약금 마감까지 미입금·대기면 다음 날 자동 취소. 원본 견적도`CANCELLED`

    - 생산라인 및 담당자 변경은 권한과 배정 조건을 검증한 후 처리하고 변경 이력을 기록한다.
    - 생산라인의 점검·고장 발생 시 정책에 따라 작업지시서의 생산계획을 자동 재배치한다.
    - 작업 상태 변경에 따라 관련 수주 상태를 반영하고, 상태 변경 이력을 기록한다.
    - 작업지시서 한 장은 하나의 생산라인에 배정되며, 날짜별 계획 수량은 별도로 관리한다.
    - 실제 생산량은 수집하지 않으며, 생산 진행 현황은 작업 상태를 기준으로 표시한다.

## 14. 배송 관리 화면 (`/shipments`)

<img src="../images/shipment_list1.png" width="500" alt="배송 관리 화면 1">

<img src="../images/shipment_list2.png" width="500" alt="배송 관리 화면 2">

<img src="../images/shipment_list3.png" width="500" alt="배송 관리 화면 3">

<img src="../images/shipment_list4.png" width="500" alt="배송 관리 화면 4">

포장 완료부터 출고·배송 완료·잔금 확인까지 한 화면에서 처리한다. 탭은 PACKING / READY_TO_SHIP / SHIPPING / BALANCE, 목록은 납기 빠른 순·페이징이다.

- 출력 데이터 항목 (Output Data):
    - 상단: `워크스페이스 > 수주 및 생산기록 > 배송 관리`, 제목 `배송 관리`
    - 상태 카드 4개(건수): 포장 완료, 출고대기, 배송중, 잔금 대기
    - 공통 목록: 수주번호, 거래처/품목, 배송지, 납기 + `납기 빠른 순 · 총 N건`·페이징
    - 포장 완료: 입금 상태, `출고 대기` 버튼 (전부 PACK_DONE인 PACKING만)
    - 출고대기: 상태·입금, 택배사·운송장·`출고`
    - 배송중: 운송장(택배사·번호·출고 시각), `상태 갱신`·`배송 완료`
    - 잔금 대기: 상태(`완료`), 잔금, 입금은 수주 상세에서 확인. 없으면 `처리할 수주가 없습니다.`
- 입력 데이터 및 검증 규칙 (Input Data & Validation):
    - 출고대기에서만 택배사·운송장 입력. 둘 다 있어야 `출고` 활성
    - 운송장 숫자만, 택배사+운송장 중복 불가, 수주당 1건
- 화면 제어 및 동작 규칙 (Behavior Rules):
    - 카드 클릭 → 해당 탭 목록 표시
    - `출고 대기` → READY_TO_SHIP
    - `출고` → 운송장 저장·SHIPPING·잔금 준비·배송 시작 알림(실패해도 출고 유지)
    - `상태 갱신`/주기 조회 → 배송완료면 COMPLETED, 잔금 미입금이면 잔금 대기
    - `배송 완료` → 수동 완료 처리(동일)
    - 수주번호 → 수주 상세
    - 조회·출고·갱신·배송 완료는 모든 역할 가능
