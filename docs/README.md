# PRODFLOW

**견적부터 생산·출고·입금까지 연결하는 내부 생산·수주 관리 플랫폼**

PRODFLOW는 휴대폰 케이스 생산시설의 임직원을 위한 내부 생산·수주 관리 플랫폼이다. 견적부터 생산계획, 포장, 출고, 배송, 입금까지의 업무를 통합 관리한다. 계약금 입금 후 작업지시를 생성하고, 날짜별 생산계획과 업무 상태를 연결해 진행 현황을 확인한다.

## 서비스 소개

수주와 생산 일정을 별도로 관리할 때 발생하는 정보 누락을 줄이기 위해, 견적·계약금·작업지시·출고를 하나의 업무 흐름으로 구성했다.

```mermaid
flowchart LR
    A[견적 작성·발송] --> B[직원의 승인 처리]
    B --> C[수주 등록]
    C --> D[계약금 입금]
    D --> E[작업지시·생산계획 생성]
    E --> F[생산·포장]
    F --> G[출고대기]
    G --> H[운송장·잔금 계좌·이메일 처리]
    H --> I[출고 확정]
    I --> J[배송 완료]
    J --> K[잔금 입금]
```

외부 회원가입과 거래처 전용 화면은 제공하지 않는다. 최고 관리자가 발급한 계정으로 접근하며, 최고 관리자·수주 관리자·생산 현장 관리자·업무 조회 담당자의 역할을 구분한다.

생산 현황은 작업 상태와 계획 수량을 기준으로 표시한다. 설비의 실제 생산량·불량 수량을 수집하는 시스템은 아니다. 배송 완료와 잔금 입금은 별도로 관리한다.

## 주요 기능

| 기능       | 내용                                                                     |
|----------|------------------------------------------------------------------------|
| 견적·수주    | 거래처·품목 검색, 납기 계산, PDF 생성·이메일 발송, 승인 견적 기반 수주 등록, 상태 이력·CSV 조회          |
| 생산계획·라인  | 계약금 입금 후 작업지시 생성, 날짜별 생산량 배정, 담당자·라인 변경, 생산·포장 상태 관리, 생산능력 변경·점검·고장 처리 |
| 결제·입금    | PortOne 가상계좌 발급·재발급·조회, 입금 웹훅 반영, 현금 계약금 처리, 결제·입금 내역 조회               |
| 출고·배송    | 포장완료 확인, 잔금 계좌 준비·이메일 전송 후 출고 확정, 스마트택배 조회, 배송 완료 처리                   |
| 거래처·품목   | 거래처 등록·수정·엑셀 일괄등록, 품목·기종 관리, 도면 업로드·조회·삭제와 Presigned URL               |
| 대시보드·일정  | 수주·생산·납기·입금 집계, 생산 캘린더·일일 생산계획, 내부 납기·라인 알림                            |
| AI 업무 조회 | Gemini·Groq 모델 선택, MCP 기반 데이터 조회·SQL 검증, 대화방 생성·제목 변경·종료               |
| 계정·인증    | JWT 인증·재발급, 최초 비밀번호 변경, 직원 계정·역할·활성 상태 관리                              |

업무별 주요 조건은 다음과 같다.

- 품목별 수주 수량은 100개 이상이며 견적 수량을 초과할 수 없다. 등록된 수주의 수량·단가·납기·배송지 수정 API는 제공하지 않는다.
- 수동입금은 계약금 전용이며, PG 발급 진행 상태와 활성 가상계좌 등에 따라 처리를 제한한다.
- 점검·고장 시 자동 재배치는 오늘 이후 준비 작업을 대상으로 한다. 생산 중·일시정지 작업의 자동 이관은 지원하지 않는다.
- 가상계좌 만료 상태는 주기적으로 갱신한다. 계약금 기한 경과에 따른 수주 자동 취소 스케줄러는 없다.

## 프로젝트 구조

```text
PRODFLOW/
├── src/main/java/net/likelion/bebc25/prodflow/
│   ├── auth/ · user/                 # 인증·직원 계정
│   ├── client/ · product/            # 거래처·생산품목
│   ├── quotation/ · customer_order/  # 견적·수주
│   ├── work_order/ · line/           # 작업지시·생산라인
│   ├── payment/ · shipment/          # 결제·배송
│   ├── dashboard/ · ai/              # 통계·AI 조회
│   └── ...                          # 공통·알림·메일·공휴일 등
├── src/main/resources/               # 설정·초기 데이터·폰트
├── src/test/                         # 테스트 코드·H2 설정
├── docs/                            # 기획·설계·문제 해결 기록
├── .github/workflows/               # CI·CD
├── Dockerfile
└── docker-compose.yaml
```

## 배포

- **CI:** `dev`·`main`의 PR·Push에서 JDK 25로 테스트를 실행한다. `docs/`만 변경된 경우 테스트 작업을 생략한다.
- **CD:** `main` Push 또는 수동 실행 시 Docker 이미지를 빌드·업로드하고, EC2에서 환경 변수 갱신과 컨테이너 재생성을 수행한다. CI와 CD는 별도 워크플로다.
- **컨테이너:** Dockerfile은 멀티 스테이지 빌드로 테스트를 제외한 실행 JAR을 생성한다. 저장소의 Compose는 MySQL을 활성 서비스로 제공하며 앱·Nginx 정의는 주석 처리되어 있다.

배포 절차는 [CI](../.github/workflows/ci.yml)·[CD](../.github/workflows/deploy.yml) 설정, 인프라
구성은 [아키텍처 문서](02_design/01_architecture.md)를 참고한다.
